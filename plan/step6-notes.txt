step6 notes: decisions and rationale for implementation choices.


Decisions taken before implementation

  BAM in brief

    A BAM file is BGZF: a series of independent gzip members of at most 64 KB, readable by any
    multi-member gzip decoder (pluk's flate2 MultiGzDecoder included) and decompressible in
    parallel. Decompressed it holds the magic bytes BAM\1, the SAM header text (verbatim), a
    binary list of reference names and lengths, and the records. A record has a fixed 32-byte
    part (reference index, 0-based position, MAPQ, FLAG, mate reference index and position,
    TLEN, lengths), then the NUL-terminated name, CIGAR as 32-bit operations, SEQ packed 4 bits
    per base, QUAL as raw Phred values (0xFF for '*') and binary typed tags. RNAME and RNEXT are
    indexes into the binary reference list.

    noodles: bam::io::Reader::new(raw) wraps the BGZF decoder; Reader::from(decoder) accepts
    another decoder (flate2 MultiGzDecoder, bgzf MultithreadedReader). header_reader() gives the
    raw header parts, read_header() a parsed sam::Header. read_record(&mut record) refills one
    reused record buffer; bam::Record decodes lazily, its accessors (name, flags, cigar,
    sequence, quality_scores, data, ...) are views into the raw bytes.

  noodles rather than an own decoder

    The guidelines prefer fewer crates; noodles-bam, -sam and -bgzf bring about 36 crates
    (indexmap, bstr, memchr, noodles-csi, ...). The format is simple enough for an own decoder
    on top of flate2 (300-400 lines), but parallel BGZF decompression would be further work.
    noodles was anticipated in step2, is well tested and provides the multithreaded reader.

  Measurements (scratch project, 1,000,000 records of 150 bases, BAM 160 MB, SAM 357 MB)

    noodles decode only, single thread                       0.84 s
    noodles decode + SAM text (noodles writer), 1 thread     1.09 s
    noodles MultithreadedReader, decode, 2/4/8 workers       0.42 / 0.22 / 0.11 s
    the same, decode + SAM text, 4 workers                   0.26 s
    samtools view (1 thread) / samtools view -@4             3.15 / 0.35 s
    pluk --sam -c on the SAM text                            0.25 s
    samtools view | pluk --sam -c                            1.42 s

    Decompression dominates and scales with threads; SAM text formatting adds about 0.25 s per
    million records, about as much as pluk's own processing of the text. Records written by the
    noodles writer were byte-identical to samtools view on this data.

  Integration: a BufRead producing SAM text

    BamReader (src/bam.rs) implements BufRead: when its buffer is empty it decodes the next
    records and writes them as SAM text into it; the header comes first. LineReader reads from
    it exactly as from STDIN. This is the isolation the plan asked for ("present it as a SAM
    text line from io.rs"), at the level of the byte stream; everything downstream is unchanged.
    The cost is one copy per line.

  Own record formatter rather than the noodles writer

    The noodles writer differs from samtools for float tags: noodles 0.00001, 3.1415927, 1e20;
    samtools (C's %g) 1e-05, 3.14159, 1e+20. pluk formats records itself, with a %g emulation
    (Rust has no %g), so that the output equals samtools view. An own formatter is also needed
    for the deferred field mask, so the work is not done twice.

  Header: verbatim text, @SQ from the binary list when absent, mismatch is an error

    The noodles parsed header regroups lines (@CO moved after @PG); the raw text keeps the order,
    so the text is written verbatim. Records use only the binary reference list. Tested with
    hand-made BAM files:
      - text without @SQ lines: samtools view -h appends @SQ lines generated from the binary list
        after the text; noodles inserts them after @HD. pluk follows samtools, so that seqlen and
        the reference length check (step4 item 4a), which read @SQ lines, work for such files.
      - text @SQ lines that differ from the binary list (chrX/77 against chr1/1000): samtools
        prints the text and names the records from the list, so its output contradicts itself;
        noodles refuses the file ("SAM header and binary reference sequence dictionaries
        mismatch"). pluk exits with an error naming the first difference: the file is broken,
        and seqlen would silently use wrong lengths.

  BAM recognised under --sam; no --bam options

    Recognising BAM costs little. BGZF is gzip, so BAM is caught by the existing gzip check, but
    BGZF does not identify BAM (bgzip-compressed SAM text is BGZF too); the content decides. The
    read buffer (128 KB) holds the whole first BGZF block (at most 64 KB), which is decompressed
    from the buffer with flate2 to compare the first four bytes with BAM\1. Nothing is consumed,
    so this works on pipes, and the untouched stream goes to the gzip text path or to the noodles
    reader (the multithreaded one included).
      - --sam / --sam-h with BAM input: read as BAM, silently, as gzip is decompressed silently.
      - BAM without a SAM option: error "input is BAM; use --sam or --sam-h". SAM mode changes how
        input is read (-k, -O12, '@' lines); switching it on implicitly would change the meaning
        of a command line because of the input format.
      - The --bam family planned in step2 is dropped: --sam reads SAM, gzipped SAM and BAM, and
        --sam/FILE gives the reference for all. pick has no --bam, so compatibility is unaffected.

  Unneeded fields as empty fields: deferred

    Agreed in principle, deferred (deferred.txt): pluk cannot yet infer which fields are needed
    (no computes), -A, -x and --sam-h need all fields, the gain is bounded (formatting is a
    fifth to a quarter of the cost, and threads remove most of the decompression cost), and an
    empty field is not a valid SAM value: FLAG must always be written for the looks-like-SAM
    check and the sequence fill. The design is a field mask passed to BamReader.

  Threads

    Decompression is multithreaded by default (4 workers) with an option for the number; 1
    gives single-threaded decompression. The name is settled in item 3 (suggestion --threads=N,
    not tied to BAM, as it may later serve other work).


Item 1: BAM detection

  peek_format (io.rs). The gzip check used fill_buf(), which sees only what one read() returned;
  on a pipe that may be too little to decompress the first four bytes of a BAM stream.
  peek_format() reads into a prefix until the format is clear, then returns the prefix in front
  of the rest of the stream (Cursor::new(prefix).chain(source)), so no input is lost and the
  decision does not depend on how a pipe delivers its bytes. This also settles the old caveat
  about a read returning fewer than two bytes.
    - Not starting with the gzip magic bytes: Text.
    - gzip: the prefix is decompressed with MultiGzDecoder (which continues into the next member,
      covering an empty first BGZF block) until four bytes are obtained; BAM\1 gives Bam,
      anything else Gzip. A truncated prefix just yields fewer bytes and more input is read;
      at end of input, or after PEEK_LIMIT (256 KiB) of input, the decision is Gzip.
  text_reader() builds the buffered (decompressing) reader for Text and Gzip. open_buffered(),
  used for dictionary files, now goes through peek_format() too; a BAM file given as a
  dictionary is read as gzip text, as before.

  STDIN is now read through io::stdin() instead of io::stdin().lock(): the locked handle is
  not Send, and item 3 hands the stream to the threads of noodles' MultithreadedReader. Each
  read() takes the lock, but reads are 128 KiB; no difference measured (1,000,000 SAM lines,
  pluk --sam -c, 0.25 s before and after).

  from_stdin(): BAM without a SAM option is an error "input is BAM; use --sam or --sam-h" (exit
  1); with --sam or --sam-h it is "BAM input is not yet supported" until item 2.

  Test data:
    sam-clean.txt   sam.txt without the lines that cannot be stored in BAM (r003 and r007 with a
                    non-numeric FLAG, shortline, r008 with too few fields, the @CO line between
                    the alignments).
    sam.bam         samtools view -b --no-PG of sam-clean.txt (samtools view -h --no-PG gives
                    sam-clean.txt back).
    sam-clean.bgz   sam-clean.txt in BGZF blocks (bgzip format, written with a small Python
                    script as bgzip is not installed), to show that BGZF text is not taken for BAM.
  Tests: bam-nosam (error), sam-bgzf and sam-clean-gz (identical output). Unit test formats in
  io.rs: text, a lone byte, empty input, bare gzip magic, gzip and BAM, each also through a
  reader that delivers one byte per read(), checking the format and that no input is lost.


Item 2: src/bam.rs, BamReader

  Dependencies: noodles-bam 0.98, noodles-bgzf 0.52, noodles-sam 0.93 (the version noodles-bam
  uses; needed for the tag Value/Array types). noodles requires Rust 1.91 or later.

  Wiring (io.rs). from_stdin(): Format::Bam with a SAM option gives
  BamReader::new(bgzf::io::Reader::new(EofCheck(source))) as the Box<dyn BufRead> that
  LineReader reads. parse_sq() is now pub, shared with bam.rs.

  BamReader. Implements BufRead (and Read): fill_buf() refills a text buffer with the SAM lines
  of the next records, up to about 128 KiB, when the previous text has been consumed. The
  header text is the first content of the buffer. One noodles Record is reused.

  Header (read_header, header_text). Read through noodles' header_reader(): magic bytes, the
  raw header text (noodles strips NUL padding), the binary reference list. The text is kept
  verbatim, a final newline added if missing. @SQ lines of the text are parsed with parse_sq:
    - none: @SQ lines from the binary list are appended (as samtools).
    - present: compared with the binary list as sets of (name, length); order is not compared
      (records refer to the binary list; samtools and noodles do not require it either). The
      first difference is an error: count, a name without @SQ line, a length. An @SQ line
      without SN/LN cannot be compared and is an error too.

  Records (format_record). Fields from the lazy noodles accessors:
    QNAME '*' if absent; FLAG; RNAME from the binary list ('*' for none, error for an index
    outside it); POS and PNEXT 0 if absent; MAPQ 255 if absent; CIGAR from the raw 32-bit
    operations ('*' if none); RNEXT '=' when equal to RNAME (and present); TLEN; SEQ from the
    4-bit codes =ACMGRSVTWYHKDBN ('*' if empty); QUAL Phred+33, '*' if empty or the first
    byte is 0xFF (as htslib).
    Tags in record order: all integer types as i, A, Z, H, f with %g, B arrays with their
    subtype and %g for floats. push_array uses a generic push_values() with a formatting
    function argument rather than a macro.
  Long CIGAR: a CIGAR of more than 65535 operations is stored in a CG:B:I tag with a
  placeholder CIGAR (kSmN). noodles' cigar() already returns the real operations; samtools
  then leaves the CG tag out, and so does pluk (is_cigar_source compares the CG values with the
  CIGAR noodles returned). Tested with a short CIGAR stored this way (bam-cg.bam).

  %g (push_g). C's %g with precision 6, from Rust's {:.5e} (for the exponent after rounding)
  and {:.N} (fixed); trailing zeros and a trailing '.' removed; exponent with sign and at least
  two digits; nan, inf, -inf, -0 as glibc. Rust rounds exact ties to even as glibc does
  (checked: 1234565 gives 1.23456e+06 in both). Unit test values taken from samtools.

  Truncated input. noodles reports a stream that ends inside a block or a record as
  UnexpectedEof ("failed to fill whole buffer"), reworded as "BAM input is truncated (...)".
  A stream that ends at a block boundary, or within the 18-byte header of a block, noodles
  takes for a complete file. EofCheck wraps the compressed stream, keeps its last 28 bytes and
  records whether the stream ended with the BGZF end-of-file marker (the empty block that
  ends every complete BGZF file); without it, pluk exits with "BAM input is truncated (no BGZF
  end-of-file marker)". samtools only warns ("EOF marker is absent") because very old BAM
  writers did not write the marker; pluk errs on the side of not producing silently
  incomplete output. The flag is an Arc<AtomicBool> as the stream will be read from noodles'
  decompression threads in item 3.

  Checked against samtools view -h --no-PG, byte for byte (pluk --sam-h -A, the -O12 trailing
  TAB of lines without tags removed): the 1,000,000-record file of the measurements, the tag
  file below, and the hand-made files. Speed (single-threaded decompression): pluk --sam -c
  on the 160 MB BAM 1.3 s (samtools view | pluk --sam -c: 1.42 s).

  Test data:
    bam-tags.txt / .bam  all tag types with extreme integer values, floats (%g cases), A, Z
                         with spaces, H, B arrays of every subtype including an empty one;
                         hard and soft clips, RNEXT '=' and another reference, negative TLEN,
                         IUPAC bases and '=', lowercase bases (BAM stores uppercase), QUAL '*'
                         with SEQ, unmapped read with SEQ and QUAL '*', a P operation, MAPQ
                         255, @CO after @PG. Made with samtools view -b --no-PG.
    mkbam.py             writes the BAM files samtools cannot make from SAM text:
                         bam-nosq.bam (no @SQ lines), bam-sqdiff.bam (an @SQ length that
                         differs from the binary list), bam-cg.bam (CIGAR in CG),
                         bam-empty.bam (header only). It contains its own BGZF writer.
  Tests (.ref files of the comparisons with samtools are samtools output):
    bam-sam, bam-samh, bam-pat     identical to the same command on sam-clean.txt
    bam-tags, bam-nosq, bam-cg, bam-empty   samtools view -h output
    bam-sqdiff, bam-truncated      errors (truncated at a block boundary and within a block)
    bam-seqlen (+ -msg), bam-nosq-seqlen, bam-samsort (runtestopt): seqlen from BAM headers,
    including @SQ lines generated from the binary list; @HD read from a BAM header.
  Unit tests: printf_g, header_sq, eof_marker (in bam.rs).


Item 3: multithreaded decompression, --threads=N

  Option. --threads=N (N a positive number), not tied to BAM so that it can later serve other
  work (gzip). Default 4; both the default and N are capped at the number of processors
  (std::thread::available_parallelism). io::bam_threads() computes the number; it is passed in
  InputSettings.threads. With 1, noodles' single-threaded bgzf::io::Reader is used (no extra
  threads); otherwise bgzf::io::MultithreadedReader::with_worker_count(N): a thread that reads
  the compressed blocks and a pool of N threads that decompress them. The stream (Peeked<Stdin>
  inside EofCheck) is Send, as the reading thread requires.
  EofCheck's flag is now stored with Release and loaded with Acquire: it is set in the reading
  thread and read in the main thread once the decoder has reported the end.

  Measurements (1,000,000 records, 160 MB BAM):
    pluk --sam -c         threads 1: 1.28 s   2: 0.46 s   3: 0.47 s   4: 0.46 s   6: 0.47 s
    pluk --sam-h -A       threads 1: 1.66 s   2: 0.77 s   4: 0.75 s   8: 0.75 s
    samtools view -@4 | pluk --sam -c: 0.37 s
  From two threads on, the main thread is the limit: SAM formatting (about 0.2 s) and pluk's own
  processing (about 0.25 s) run there in sequence, where samtools | pluk runs them in two
  processes. The deferred item "formatting in a separate thread" would address this. The
  default stays 4: with longer reads decompression takes a larger share.

  BamReader change: one record per refill. Item 2 refilled the text buffer with records up to
  128 KiB. On a stream that is still being written (a pipe from an aligner) this blocks until
  enough records have arrived or the stream ends, although lines are already available; with
  text input the reader passes on what the pipe delivers. refill() now formats one record per
  call; the work per record is the same and the measurements did not change.

  Early exit with a stalled producer. When pluk stops before the end of the input (an error such
  as an unknown column), noodles' MultithreadedReader joins its reading thread on drop. If that
  thread is blocked reading a pipe whose writer is idle, pluk waits until the writer writes or
  closes; a writer that keeps writing ends the wait with its next write. With --threads=1 there
  is no such thread. This is accepted; the alternative (leaking the reader with mem::forget)
  was judged not worth the opacity.

  The help text for --sam now mentions BAM input (missed in item 2).

  Tests: bam-tags-t1 and bam-tags-t2 (same output as bam-tags, which now runs with the default
  of 4 threads), bam-truncated-t1 (the truncation errors with the single-threaded reader),
  threads-errors, threads-text (accepted with text input). o.help.ref and o.help-long.ref
  updated. Unit tests threads in opt.rs and io.rs.
