
Notes for plan/step26.txt (renaming computes).


Planning

  The extent was judged before starting: the map of step11 already compiles one compute
  per column; renaming changes the target names and makes __ point at the source column;
  the keep-original form touches the output selection. The user changed pick's
  keep-original syntax to P//SPEC//S (symmetric); agreed: exactly three shapes, mixed
  delimiters (pick's P/SPEC//S) and a two-part keep form refused with hints, the keep
  form needs '::'; a generated name equal to an existing column always an error; pick's
  suffix warning kept as a warning.


Item 1: NAME shapes, prefix/suffix renaming, keep-original

  compute.rs: parse_name finds the runs of '/' in the raw NAME (a literal '/' is %2F, so
  every '/' is a delimiter) and accepts one single run (SPEC/S), two single runs
  (P/SPEC/S) or two double runs (P//SPEC//S); everything else is an error with a hint.
  P and S are %-decoded; SPEC is parsed as a column specification and always kept as a
  map, so a single plain name goes through the same per-column loop. ComputeSpec.rename
  (Rename: prefix, suffix, keep). The suffix warning is given at parse time.

  The per-column loop now produces (target name, source column) pairs: the target is
  P + name + S (item 2 will put capture group 1 in place of name); two equal targets are
  an error naming both columns; a target that equals the source name is the in-place
  case (the -i rule applies; with // an error); any other target that exists already is
  an error. __ resolves to the source column (before: the target's current binding,
  which is the same column for a plain map). Compute.keep holds the source column for
  P//SPEC//S.

  main.rs: the computed list for column arguments (computed_keep) puts the source column
  just before each new column of a keep compute; -A and -x get the list without them (the
  originals are output anyway, and an original excluded with -x stays excluded).
  --test-compute shows the renaming.

  Checked against pick: new_/fib/, /fib/_new, fib/_new, new_/fib/_x, a regex and a list
  with a prefix: identical; P//SPEC//S against pick's P/SPEC//S for a prefix, a suffix
  and a list: identical.

  Tests: rename (the pick examples, the keep forms, in place with -i, -A, -x, -A<N>,
  a %2F prefix, the warning, the errors, --test-compute). compute-parse-errors: the
  former 'not yet supported' case p/x/s is now valid; p/x//s takes its place. Unit test
  rename_shapes; errors extended. help refs.


Item 2: capture group 1 naming

  colspec.rs: expand_bases returns each selected column with capture group 1 of the '+'
  regex element that selected it, when the regex has a capturing group (the anchored
  wrapper \A(?:..)\z is non-capturing, so group 1 is the user's); a group that does not
  take part in the match or matches empty is an error naming the column. expand is now
  expand_bases without the groups.

  compute.rs: in the per-column loop the base of the new name is group 1 if there is
  one, else the column name; a column named by a group is renamed even without P and S
  (an empty Rename stands in), so the renaming rules apply: equal generated names and a
  generated name that exists are errors; a group equal to the column's own name
  (+(fib)) is the in-place case and needs -i. Duplicates merged keep the first element's
  group. A non-capturing group ((?:..), written (?%3A..) in a NAME, as ':' separates list
  elements) leaves the plain map.

  Behaviour change, as decided: -i '+num(\d)::..' now creates columns 1 2 4 instead of
  redefining num1 num2 num4; no existing test depended on it.

  Checked against pick: +num(\d) (columns 1 2 4), with a prefix and suffix, the collision
  of n(u)m\d (pick also refuses, with another message), keep-original with a group
  against pick's P/SPEC//S: identical.

  Tests: rename-group (the cases above, a list mixing a grouped regex and a name, -A, -k,
  the errors). help refs.
