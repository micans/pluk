
Notes for plan/step29.txt (the manual: sections 4-9).


Planning

  Agreed without changes: body sections in pick's style (invocations first, then the
  details), operators linked to the reference rather than described again, options
  described in the body; new small data files where needed; an option coverage check,
  reported at the end of this step and an error once section 10 is written.


Item 1: section 4, selecting columns

  Names, lists and patterns (a pattern must match the whole name; an unknown name or a
  pattern without a match is an error); repeated columns (output once; -U); -k ranges
  (2-4, 5-, O+S-E*M); -A -A<N> --A=NAME -x -U; -u and -R; ragged input -O<N> and why
  --sam implies -k -O12. New data file doc/ragged.txt (a header of three names, a short
  and a long row). 8 example blocks, outputs produced by running them (an authoring
  script that fills a fragment's console blocks and puts it in place of the section's
  outline; not part of the repository) and read against the text: one addition, that -R's
  column _ is written as an empty name in the output header.


Item 2: section 5, filters and assertions

  A filter keeps a row when it passes every filter; the operators by kind, linked to
  section 15 rather than described again; VALUE as a constant, ^CONSTANT or :OTHER, then
  %-decoded (so %3A and %5E give a literal colon and caret; checked by running pluk, the
  first draft wrongly said a leading '^' was kept literally); @@ before the computes sees
  only input columns (a computed column in @@ is an error, shown), @ after them; a
  multi-column handle requires every column to pass; -o and -s (any instead of all);
  --other; @assert@ and @@assert@, their message and exit status 1, --assert-other. The
  manual's opening note now says sections 1 to 5 are complete (item 1 had left it at 1 to
  3).


Item 3: section 6, computes

  NAME::SPEC and NAME:=SPEC; the stack language (^ : ,; a SPEC not starting with one of
  them starts with a column; what is left on the stack is concatenated, shown with
  'kg^1,dd:bruised'); splats and the *all operators; NA from an operator that needs a
  number; --seed (--num-perl only referred to section 3); unnamed computes; output
  positions with -A, -A<N>, --A=NAME; -i and __ (earlier computes see the old value);
  -i over lists; renaming P/SPEC/S, P//SPEC//S, capture group 1; -e (with %20 for a
  space in a value).

  Two facts from --help were missing from section 5 and are added there: with ~ and /~
  a :OTHER value is matched as a fixed string; assertions are checked before the filters
  of their stage, and -o and -s do not apply to them.

  Observed, not changed: when -i redefines a name that is also output (-i picker kg
  'kg::..', or v:= followed by two v:: computes) pluk writes '-- Identical output column
  names exist (will make unique)' to stderr, but the output has the column once and
  nothing is made unique. The notice looks spurious; for the user to decide.


Item 4: section 7, dictionaries and quantiles

  New data files in doc/: prices.txt (fruit and price, no header; plum deliberately
  absent, so map gives the key and a product NA), fruits.txt (a table: fruit colour season
  stone), trees.fa (sequences for three of the trees, one over two lines, one with a
  description after the identifier; the missing trees show __EXIT__, the default of
  --fasta-dict). The section covers --kd --fd --cd --fasta-dict --td (^KEY, /DEFAULT),
  the synonyms, gzip, defaults and __EXIT__, merging (later values replace earlier ones,
  with a message; dord counts first appearance over all of them), the dictionary filters
  (defaults play no part), --quant-NAME with qnl and qnu. Facts checked by running pluk:
  in an --fd file a repeated key takes the later value silently, in a --td table it is an
  error; columns of an --fd file after the second are ignored; --quant steps that
  decrease are an error.


Item 5: section 8, state across rows

  New data file doc/exons.txt (genes foo bar baz with 3, 2 and 1 exons): pick's intron
  example with --group, groupi and groupno shown, and the single-exon gene showing that a
  group of one row gives no output; --group-first-ref for the span from the first exon.
  Registers (named by a constant, per row, shared between computes), rowno r0wno lineno
  (rows rejected by filters are counted; lineno includes the header), --pstore and pload
  (the previous row is the previous one that passed the @@ filters, shown against @),
  --pstore/LIST/DEFAULT and the //0 counter. All facts checked by running pluk.


Item 6: section 9, input and output; the option coverage check

  Section 9: gzip input (recognised by its first bytes), -/PAT and -//PAT (also before the
  header), -h -c -E<N>, --demux with --demux-dir, the tally (shown with 2>&1, as it has
  no pluk: prefix) and the file created for rows rejected by @ filters, a computed :=
  column naming the demux files, gzip output files (.gz .gzip) for --other,
  --assert-other and --demux, --demux-buffer and -F (no effect), --idx-list --name-list
  --idx-map, --progress (dots shown with the output discarded), --threads (pointer to
  section 10), -H/--help, --version (no example: its output changes), -l, --list-ops-tsv,
  -z/-zz. --other and --assert-other themselves stay in section 5.

  Option coverage check (decision 3): test/optcheck.py, run by 'make rundoc' after
  opscheck.py. It takes every word of pluk --help that looks like an option, reduces it
  to a stem (--kd-NAME=FILE -> --kd, -A<N> and -O12 -> -A -O, --kdict- -> --kdict; a
  combination of short options such as -kO12 stands for each letter; words after '%'
  such as %-decoded are not options), and looks for the stem in the manual, not
  followed by a letter or '-' plus a lower-case letter (so --sam-h is no mention of
  --sam). 65 options; 4 not mentioned, all SAM (--sam-nonf --sam-aln-xy --sam-narrow-xy
  --sam-ND-adjust), for section 10. Report only for now; --strict makes it an error, to
  be switched on in the Makefile when section 10 is written. The optional reverse check
  (options the manual mentions that pluk lacks) is not done: section 14 will name pick
  options that pluk does not have, so it would need an exception list.
