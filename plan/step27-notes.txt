
Notes for plan/step27.txt (documentation infrastructure; manual skeleton).


Planning

  The manual's design was agreed in discussion and written to plan/MANUAL.design.txt
  (descriptions in the manual's prose with generated signature lines, option A;
  --list-ops-tsv; tested console examples; Python 3 for the checkers). Decided before
  starting: the scripts live in pluk/test/; operators without a description are reported
  only until the reference is written.


Item 1: --list-ops-tsv

  opt.rs: Parsed::ListTsv for --list-ops-tsv (an early exit, as -l and --help); help text.
  list.rs: tsv() writes the same lines as -l (compute operators by category in -l order,
  then the filter operators, category 'filter'), with the five fields name, category,
  operands, result, description separated by TABs and no header. A unit test checks that
  no field contains a TAB or newline, so every line has exactly five fields.

  Tests: list-ops-tsv (the listing, the count of lines with another number of fields (0),
  the number of lines against the number of operator lines of -l). help refs.


Item 2: the example checker

  test/doccheck.py PLUK DOCUMENT..: extracts the console blocks (fences of three or more
  backticks, up to three spaces of indentation, the fence's indentation removed from the
  content lines as CommonMark does, so blocks inside list items work); skips a block
  preceded by <!-- notest -->; splits each block into commands ('$ ', backslash
  continuation) and their expected lines. The commands of a document run in order, in a
  fresh copy of the document's directory (so mkdir and output files do not touch
  pluk/doc), with stdin from /dev/null and PLUK's directory first on the PATH. Matching as
  MANUAL.design.txt section 4: 'pluk:' lines must occur in stderr in order; the others
  must match stdout, '...' standing for any number of lines; white space runs are one
  separator; the exit status is not compared. A failure shows the command, the expected
  lines, stdout and stderr; the run ends with a tally and exit status 1.

  Checked on a scratch document: a wrong value and a wrong stderr message fail, an
  elision and a notest block behave.

  test/Makefile: target rundoc, part of make test, runs the checker on DOCS
  (INTRODUCTION.md, SAM-NA.md).

  SAM-NA.md: its examples became console blocks on a new data file, doc/mixed.sam (the
  read of reads.sam and an unmapped read), so they run: the NA report, the NA text in a
  later compute, the numeric filter's count, @@2/none/4 for unmapped reads.
  INTRODUCTION.md: '52-base transgene' corrected to 53 (the checker cannot see prose).

  The introduction's demux example showed the tally, which pluk writes to stderr without
  a 'pluk:' prefix, so it did not match the convention. Resolved with the user: the
  example now runs pluk with -q (which silences the tally) and shows ls crates, the
  four .txt files; the convention stays as it is.


Item 3: PLUK-MANUAL.md skeleton, the signature checker

  doc/PLUK-MANUAL.md: the preamble (as the user edited it in INTRODUCTION.md), a note
  that the manual is being written, the headings of sections 1 to 14 with a line on what
  each will cover, and section 15, the operator reference: per category (in -l order) a
  heading #### `NAME` with a marker <!-- op NAME --> and the generated signature line
  `OPERANDS` → `RESULT` — DESCRIPTION for each of the 218 operators. Generated with
  opscheck.py --skeleton.

  test/opscheck.py PLUK MANUAL: reads pluk --list-ops-tsv; for every marker compares the
  next line with the generated signature (an error if it differs), reports a marker for an
  operator pluk does not have (an error), and counts operators missing from the manual and
  markers without a description (text before the next heading or marker), which are only
  reported (decision b). --update rewrites the signature lines in place and prints the
  block for every operator missing from the manual, to be placed by hand (the placement is
  an editorial choice). Self-tested on a modified copy: a changed signature, a stale
  marker, a removed operator and a described one; --update restores the signature exactly.

  test/Makefile: rundoc also runs opscheck.py on the manual; the manual is added to the
  documents of doccheck.py (no console blocks yet). The command for refreshing the
  signatures after an operator change is noted in the Makefile.
