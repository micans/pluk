step14 notes: decisions and rationale for implementation choices.

  Decisions: step14.txt (decisions 1-8).


Item 1: operand position of the pattern; delg ed edg; deferred.txt

  Files: ops.rs (Prepare::ConstRegex(pos); delg ed edg; substitute, perl_matches,
  replace_matches; del moved onto substitute), compute.rs (const_regex with the
  position), opt.rs (help), deferred.txt (sprintf, reqm).

  Prepare::ConstRegex now carries the pattern's position below the top of the stack: 0
  for del and delg (x p), 1 for ed and edg (x p s), as pick's compile_compute special case
  (it looks at the token before the operator for del, two before for ed). The constant
  stays on the run-time stack and is popped unused; the operator uses the regex compiled
  at compile time.

  substitute() pops the replacement (if any), the pattern constant and x; an NA x or
  replacement gives NA (del of an NA, which used to give the text NA, now gives NA).
  ed and edg replace with the replacement as literal text (decision 3: in Perl's
  s/$p/$s/ the replacement is a variable, so $1 in it stays).

  Empty matches. Checking the global operators against Perl (perl -lpe 's/p/-/g') showed
  that the regex crate's iteration (find_iter, replace_all) never allows an empty match
  directly after a non-empty one, while Perl does: s/a*/-/g on aaa is -- in Perl and - with
  the crate; on baab -b--b- and -b-b-. Python adopted Perl's rule in 3.7. pluk iterates
  itself (perl_matches): find_at from the current position; an empty match is refused
  only at the position of the previous empty match, and the search then moves on by one
  byte. With this, x* a* \b b*$ a| (?:) ^ $ a? (a|b)* on abc, '', aaa, baab all give
  Perl's results. Not reproduced: after an empty match Perl backtracks into a longer
  match at the same position, which matters for lazy patterns that can match empty (a*?
  on aaa: Perl -------, pluk -a-a-a-); the regex crate cannot express 'a non-empty match
  starting here'. Recorded in step14.txt (decision 5) and guidelines.txt.

  Test pitfalls met: perl -pe keeps the newline in $_ (extra empty matches at the end;
  use -lpe); in a compute, ':' and '^' in a pattern must be written %3A and %5E.

  Checked against pick (--num-perl): regex-ed (delg ed edg on data.txt and big.txt, with
  character classes, groups and $1 in a literal replacement, an empty replacement, the
  empty-matching patterns C* and n*, an anchor written %5E) is identical. regex-empty
  keeps the empty-match cases checked against Perl.

  Tests: regex-ed, regex-empty, regex-ed-edge (underflow, a column pattern, an empty and
  an invalid pattern, NA). Help refs. Unit test in ops.rs (perl_matches).


Item 2: edbr and edgbr

  Files: ops.rs (expand_groups, op_edbr, op_edgbr), opt.rs (help).

  expand_groups writes the replacement for one match as pick's do_ed_br_helper: $ followed
  by digits, all of them ($12 is group 12, not group 1 and a 2), is that group's text,
  empty if the group did not take part or does not exist; $0 is the whole match; a $ not
  followed by a digit, and all other bytes, are literal. The regex crate's own expansion
  is not used: it reads $1a as a group named 1a, and ${1} syntax would be new to pick
  users.

  edbr takes the first match (Regex::captures); edgbr takes the match positions of
  perl_matches (item 1, Perl's empty-match rule) and the groups of each from
  Regex::captures_at at the match's start, which finds the same match (leftmost-first
  search from that position).

  Checked against pick (--num-perl): regex-br (swapped groups, a group that does not take
  part, a group that does not exist, $0, $1x, $$1 (a literal $ and group 1), empty
  matches with n*; big.txt) is identical.

  Tests: regex-br. Help refs. Unit test in ops.rs (expand_groups).


Item 3: get and npat

  Files: ops.rs (match_op, op_get, op_npat), opt.rs (help).

  get gives group 1 if it took part in the first match, else the whole match, and an
  empty string if there is no match: pick's (defined($1) ? $1 : $&). With
  Captures::get(1).or(get(0)), a pattern without groups gives the whole match as well.
  npat counts the matches as pick's '$n++ while /p/g', using perl_matches (item 1), so
  empty matches count as in Perl. Both take the pattern as the top operand
  (ConstRegex(0)); an NA x gives NA.

  Checked against pick (--num-perl): regex-get (vowel pairs, groups that do and do not
  take part, no match, counts of single characters and classes, n* with empty matches,
  \d on floats; big.txt with x*) is identical. regex-get-edge keeps npat's empty-match
  counts checked against Perl (x* a* a| a? \b on abc, '', aaa, baab), a group that does
  not take part, no match, NA and the refused empty pattern.

  Tests: regex-get, regex-get-edge. Help refs.


Item 4: \Q...\E

  Files: io.rs (expand_quotes; compile_pattern applies it), colspec.rs (expands before
  wrapping), opt.rs (help).

  expand_quotes replaces the text between \Q and \E (or the end of the pattern) by its
  regex-escaped form (regex::escape). It scans escape by escape, so \\Q (an escaped
  backslash followed by Q) is not a quote; pick's own substitution (s/\\Q(.*?)\\E/
  quotemeta($1)/eg in compile_re) would take it as one. A \E outside a quote is dropped,
  as Perl ignores it. Without \Q or \E the pattern is returned unchanged, and expanding
  twice gives the same result.

  compile_pattern expands every pattern, so \Q...\E works in -/PAT and -//PAT, the ~ and
  /~ filters, the regex operators, and '+' column regexes. pick supports it only where
  its compile_re is used (filters and computes); in its -/PAT and column regexes the
  pattern comes from a variable, where Perl does not process \Q. The '+' column regexes
  are wrapped as \A(?:...)\z; colspec.rs expands the user's pattern before wrapping, so
  that an unterminated \Q does not quote the wrapper (compile_pattern then expands again,
  which changes nothing).

  Checked against pick: regex-quote (\Q.\E in del, ed, get, npat, and in a ~ and a /~
  filter) is identical. regex-quote-other (pluk only): -/PAT, a column regex with a
  terminated and an unterminated \Q, an unterminated \Q in a compute, an escaped
  backslash before Q.

  Tests: regex-quote, regex-quote-other. Help refs. Unit test in io.rs (quotes).
