
step1 notes: rationale for implementation choices.


Item 1: reading lines

  Line reading. src/io.rs defines LineReader with a method next_line() that reads one line into a
  Vec<u8> owned by the LineReader (field 'line'). The buffer is cleared, not freed, before each line,
  so after the first few lines no allocation takes place. The call used is BufRead::read_until(b'\n'),
  which copies bytes from the read buffer into 'line' up to and including the newline; the newline is
  then removed. A last line without a newline is returned as a normal line.

  Rejected: BufRead::lines(), as used in the earlier main.rs. It allocates a new String per line and
  requires valid UTF-8; a line with invalid bytes produces an error, which the earlier code printed
  and skipped, silently losing that line. pluk handles bytes (DATASTRUCTURE-cell.design.txt, 1).

  Why not an Iterator. Rust's Iterator trait returns items that must outlive the next call to next().
  A slice into a buffer that is overwritten by the following line cannot satisfy that, so a real
  Iterator would have to return an owned copy per line -- the allocation we want to avoid. A
  'while reader.next_line()? { ... }' loop is the standard idiom for this case and corresponds to
  'while (getline(...) != -1)' in C.

  Buffered IO. Two layers, as with stdio in C:
    - BufReader (128 KiB) on STDIN. read_until() works on this buffer; the read() system call is only
      made when it is empty. This is equivalent to a FILE* with a large setvbuf() buffer.
    - For gzip input a second BufReader sits on top of the decoder. The decoder reads compressed
      bytes from the first BufReader and produces decompressed bytes into the second.
  The reader is stored as Box<dyn BufRead>: a pointer to either kind of reader plus a table of function
  pointers (comparable to a struct of function pointers in C). The cost is one indirect call per line,
  which is negligible next to the work per line.

  Output. Rust's stdout flushes at every newline, even when not writing to a terminal (unlike C stdio).
  main.rs wraps it in a 128 KiB BufWriter, so a write system call happens only when that buffer fills.
  The buffer is flushed explicitly at the end, so a write error at that point is reported rather than lost.
  Lines are written with write_all() on the raw bytes; no UTF-8 conversion takes place.

  Compressed input. The first two bytes are inspected with fill_buf(), which returns buffered bytes
  without consuming them. The bytes 1f 8b identify gzip; such input is decoded with flate2's
  MultiGzDecoder, which continues across concatenated gzip members. bgzip files (BAM, .vcf.gz,
  tabix-indexed files) consist of such members, so they are read correctly; this is also why plain
  GzDecoder is not used (it stops after the first member). flate2 uses miniz_oxide, a pure Rust
  implementation, so no C zlib is required. Other formats (zstd, bzip2, xz) are not supported; they
  can be added later in the same place.
  Caveat: the detection assumes the first read returns at least two bytes, which holds for files and
  pipes at the start of input.

  Broken pipe. Rust ignores SIGPIPE, so in 'pluk ... | head' writing after head exits gives an error
  of kind BrokenPipe rather than terminating the process. main() treats this as normal termination
  (exit status 0), matching what the shell user expects.

  Errors. run() returns std::io::Result<()>; the '?' operator returns early from run() with the error,
  which main() prints. This replaces explicit 'if (r < 0) { perror(...); exit(1); }' checks.

  Naming. The module is called io (src/io.rs), as in the step file. Within pluk 'io::' refers to
  this module and the standard library one is written 'std::io::'. If this proves confusing the
  module can be renamed (e.g. input.rs).

  Tests. pluk/test/Makefile, in the style of pick/test. 'make test' in pluk/ builds the release binary
  and runs it. The item 1 tests cover plain and gzip input, concatenated gzip members, a missing final
  newline, non-UTF-8 bytes, empty input and a broken pipe (exit status 0).


Item 2: --test-comment / --tc

  LineReader separates physical reading (read_line, private) from accepting lines (next_line, public).
  next_line() skips lines starting with '#' while no line has been accepted yet, and only if the
  setting is on. Later skip rules (pick's -/PAT and -//PAT) belong in next_line() as well.

  Settings reach io.rs through the struct io::InputSettings, filled in by main.rs from opt::Config.
  io.rs therefore does not depend on clap or on opt.rs; when argument parsing is replaced, io.rs is
  unaffected. -k and -O (item 4) will be added to InputSettings.

  Counters: n_lines (physical lines read), n_skipped, n_accepted. The line count printed is the
  physical line number, as used by pick in its error messages ($.).

  The option is defined with clap's 'visible_alias', which shows --tc in --help.

  Tests are in the runtestopt target of test/Makefile, separate from the permanent tests.

  To note for step2: clap reserves -h for --help and -V for --version by default. pick uses -h for
  "do not print header". Clap's automatic -h will need to be disabled (disable_help_flag) when -h is
  implemented.


Item 3: splitting on TAB, --test-i

  Representation. src/row.rs defines

      struct Row {
          line:   Vec<u8>,              // the line, newline removed
          fields: Vec<(usize, usize)>,  // (start, end) byte offsets of each field
      }

  LineReader owns one Row and refills it for every accepted line. Skipped lines are not split.

  How line and fields share memory. There is one allocation holding the bytes of the line: the
  Vec<u8> 'line' (in C terms: a char* with a length and an allocated capacity). The fields are
  not copies; they are offsets into that memory. Row::field(i) returns &line[start..end], a slice,
  which is a pointer to byte 'start' of the line plus the length end - start -- the same as
  (line + start, end - start) in C. Writing a field to output therefore writes directly from the
  line buffer. For

      line:    a \t b c \t \t d          (bytes 0..7)
      fields:  (0,1) (2,4) (5,5) (6,7)

  the third field is empty: start equals end. Both Vecs are cleared, not freed, for every line, so
  in steady state no allocation takes place.

  Safety. The slice returned by field(i) borrows the Row. The compiler rejects any attempt to read
  the next line (which mutably borrows the Row) while such a slice is still in use, so a dangling
  pointer into an overwritten line cannot occur. Indexing is bounds-checked: field(i) with
  i >= n_fields() panics (aborts with a message) instead of reading invalid memory.

  Splitting. A plain loop over the bytes, pushing (start, i) at every TAB, then the final field.
  An empty line is one empty field, as in pick (Perl's split on an empty string is special-cased
  in pick to ("") ). A faster byte search (the memchr crate, SIMD) is possible if profiling shows
  splitting to matter; it would not change the interface.

  --test-i <N> is 1-based, consistent with the column names 1..N that -k will use. Clap rejects
  0 and non-numbers. A line with fewer than N fields prints an empty field; validation is item 5.

  Tests. Unit tests for split_fields() are in src/row.rs (a #[cfg(test)] module, compiled only by
  'cargo test'). 'make test' runs them before the Makefile tests. --test-i tests are in the
  runtestopt group. The outputs were checked against 'cut -f<N>' for several columns.


Item 4: -k, -c, -O, B_header, counters

  Settings. io::InputSettings gains B_header (true unless -k) and omega (-O <N>). The name B_header
  follows the plan; Rust convention is snake_case (b_header), so the struct carries
  #[allow(non_snake_case)] to silence the compiler warning.

  First line. LineReader::from_stdin() reads the first accepted line before returning (read_first()).
    - B_header: the line is moved into LineReader.header, a second Row. Its fields are the column
      names; no separate copy is made (item 6 adds the name list and dictionary). The move is
      std::mem::swap(&mut self.header, &mut self.row): the two Row structs (pointers, lengths,
      capacities) are exchanged, the line bytes stay where they are.
    - no B_header (-k): the line stays in self.row and the flag 'pending' is set, so that the first
      call of next_line() returns it without reading.
  This keeps the main loop uniform: next_line() returns data lines only, header excluded.

  Number of columns (n_columns): with B_header the number of header fields; otherwise the -O value
  if given, else the number of fields in the first line. Empty input gives 0 (or the -O value).

  -O requires -k: checked in opt::parse_args() after clap has parsed, message as in pick. clap
  accepts both -O3 and -O 3; pick accepts only -O3.

  Counters. n_accepted counts data lines (pick's Nkeep before filtering). With -O <N>, next_line()
  counts lines with fewer than N fields (n_short_rows) and more than N fields (n_overflow_rows).
  The temporary option --test-counts prints all counters to STDERR, to make them testable.

  -c prints n_accepted after reading all input, as pick prints Nkeep. The values agree with pick
  for data.txt, data.txt with -k, and big.txt. Empty input prints 0; pick prints 0 as well but also
  a spurious warning ("Line tally check failed"), which pluk does not replicate.

  Output during step1: main.rs prints the header line itself (with its line number), then the data
  lines, so the output of items 1-3 is unchanged and the earlier tests serve as regression tests.

  Exit status for errors: pluk exits with 1, pick (Perl die) with 255. Decided: keep 1.


Item 5: validation, -R, -O

  Validation is done in LineReader::next_line(). Without -O every data line must have n_columns
  fields; otherwise next_line() returns an error with pick's message
  ("Header/<N> column/<M> count difference at line <L> (consider -R or -O<N>)"). With -k the same
  check applies, n_columns being the field count of the first line.

  The error is returned as a std::io::Error of kind InvalidData, so that next_line() keeps a single
  error type (std::io::Result). A dedicated error type (a Rust enum listing pluk's error cases) is
  the more idiomatic choice once there are more kinds of error; not needed yet.

  -R: with B_header, n_columns is the number of header fields plus one, unless the first header
  field is empty (pick behaviour: that field already is the row name column). The flag
  row_column_added records this for item 6, where the column name '_' is assigned.
  -R with -k is an error (step1-context.txt).

  -O <N>: Row::split_fields_limit(n), as decided in step1-context.txt. The loop stops when n-1
  fields have been found; the remainder of the line is field n. The return value is a
  std::cmp::Ordering (Less / Equal / Greater), the standard Rust type for a three-way comparison,
  stored in LineReader.split_order and used for the short/overflow counters. Field contents were
  checked against pick (pick -kO<N> <i>) for several N and i, including merged and padded fields.

  Tests that used deliberately ragged input without -O now fail validation; they were given
  consistent input or -kO<N> (multigz, nonewline, tc-noskip, tc-midfile, ti-empty). Only multigz
  and nonewline changed output, because their input changed.
