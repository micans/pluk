  Outcome of the discussion (rationale in step7-notes.txt, numeric model in NUMERIC.design.txt)

  Filters are given in the trailing argument list, mixed with column names as in pick:
  @NAME OP VALUE (filter after computes) and @@NAME OP VALUE (filter before computes). Computes
  (x::..., x:=...) are recognised and refused as not yet supported. VALUE is %-decoded; :NAME
  compares with another column per row; a leading ^ forces a literal value (^:x is ':x').
  Multiple filters are ANDed; -o ORs the @ filters, -s the @@ filters. Without computes @ and @@
  differ only in when they are applied; the structure anticipates computes. Column names in
  filters are plain names (a leading '+' is "not yet supported" until the column specification
  step); with -k, column numbers.

  Numeric filters follow NUMERIC.design.txt: a value that is not a number (empty, 'fox', '0x10',
  ' 4') makes the comparison fail and is counted (pick: such values are 0); a non-numeric
  constant is an option error; integer syntax that fits Int gives I, anything else accepted by
  Rust's f64 parser gives F (inf, nan with IEEE semantics). New modules: num.rs (Int, Num,
  parsing, comparison via the dispatcher) and filter.rs (parsed filters, per-row evaluation on
  the field bytes). Bit filters take abs() as pick, but a float value fails and is counted (no
  implicit f -> i).
