  Outcome of the discussion (rationale in step7-notes.txt, numeric model in NUMERIC.design.txt)

  Filters are given in the trailing argument list, mixed with column names as in pick:
  @NAME OP VALUE (filter after computes) and @@NAME OP VALUE (filter before computes). Computes
  (x::..., x:=...) are recognised and refused as not yet supported. VALUE is %-decoded; :NAME
  compares with another column per row; a leading ^ forces a literal value (^:x is ':x').
  Multiple filters are ANDed; -o ORs the @ filters, -s the @@ filters. Without computes @ and @@
  differ only in when they are applied; the structure anticipates computes. Column names in
  filters are plain names (a leading '+' is "not yet supported" until the column specification
  step); with -k, column numbers.

  Numeric filters follow NUMERIC.design.txt: a value that is not a number (empty, 'fox', '0x10',
  ' 4') makes the comparison fail and is counted (pick: such values are 0); a non-numeric
  constant is an option error; integer syntax that fits Int gives I, anything else accepted by
  Rust's f64 parser gives F (inf, nan with IEEE semantics). New modules: num.rs (Int, Num,
  parsing, comparison via the dispatcher) and filter.rs (parsed filters, per-row evaluation on
  the field bytes). Bit filters take abs() as pick, but a float value fails and is counted (no
  implicit f -> i).

  Items

  1   Argument parsing of @ and @@ filters, -o and -s, constants and :NAME, num.rs, filter.rs.
      Numeric /lt/ /le/ /eq/ /ge/ /gt/ /ne/ and string ~lt~ ~le~ ~eq~ ~ge~ ~gt~ ~ne~ (byte
      comparison). End-of-run count of non-numeric values. Tests ported from pick where
      possible. Commit.

  2   = /= ~ /~ . ~ matches anywhere (as pick); the regex dialect is that of the regex crate
      (differences documented, as for -/PAT). Commit.
        - = and /= are byte equality (as ~eq~ ~ne~); an empty VALUE is allowed (@x= selects
          empty fields).
        - ~ and /~ with a constant: regex::bytes with Unicode mode off, as -/PAT (io.rs
          compile_pattern). Compiled during option parsing, so a syntax error is an option
          error. An empty pattern is refused (in Perl an empty pattern silently reuses the
          last successful pattern; -/PAT also refuses it). ^VALUE is still a regex; ^ only
          means 'not a column reference'.
        - ~ and /~ with :NAME: a fixed-string (substring) match of the other column's value,
          not a regex (pick compiles the value as a regex per row). Matching can never fail,
          needs no cache, and column values often contain regex metacharacters (. | + ( in
          identifiers). An empty value is the empty substring: ~ always matches, /~ never.
          This is a difference from pick (guidelines.txt). Regex-from-column, if ever wanted,
          would get its own spelling.
        - '/' and '~' in a pattern are written %2F and %7E (item 1's parser).
        - Tests: pick's @x=... invocations, filter-regex (labelled invocations, a dialect
          difference), filter-regex-column, errors (empty pattern, regex syntax).

  3   ~isin~ ~isnotin~ ~hasval~ ~hasnotval~ (dictionary lookups). Commit.
        - Semantics as pick: ~isin~ is true if the field is a key of the dictionary;
          ~hasval~D~v if the key is present and its value equals v (bytes); ~isnotin~ and
          ~hasnotval~ negate (a missing key passes ~hasnotval~). Dictionary defaults
          (NAME/default, __EXIT__) play no part.
        - VALUE is a dictionary name, resolved when filters are compiled (after the header,
          so that seqlen and --td column dictionaries exist); an unknown name is an error
          (pick: 'Dictionary [D] not found', at option parsing). A leading ':' or '^' in VALUE
          is refused (pick looks for a dictionary named ':y').
        - The ~v argument of ~hasval~ ~hasnotval~ is required, separated by '~' (pick also
          accepts '/' but keeps it in the value), %-decoded, may be empty. A further '/' or
          '~' in it is refused with the %2F / %7E hint (pick takes the rest literally). A
          leading ':' is reserved (not yet supported) for a later comparison with a column.
        - The parser splits VALUE and the extra argument generally; per operator the extra
          argument is refused, required, or (item 4: /ep/ /om/) optional.
        - Lookup on the field bytes without copying. Measure ~isin~ with the default hasher
          (deferred.txt: faster hasher) and record the timing in the notes.
        - Tests: big-isin (from pick, big.keep.txt), ~isnotin~, ~hasval~/~hasnotval~ with
          --fd and --cd (empty value, a dictionary with a default), ~isin~seqlen on SAM
          input, errors (unknown dictionary, missing ~v, ':' and '^' in VALUE, ':' in v).

  4   /ep/ /epx/ /om/ /omx/ with the optional extra argument; defaults 0.0001 and 2 as pick.
      Commit.
        - Semantics as pick: /ep/ x in [y - eps, y + eps]; /om/ |x| in [|y| / k, |y| * k];
          /epx/ /omx/ negate.
        - The band is an optional extra argument separated by '/' (a '~' separator is refused;
          a leading ':' is reserved). It must be a number (an option error otherwise; an
          empty band is refused); eps >= 0 (eps = 0 is exact equality; pick takes 0 as the
          default), k >= 1 (pick takes 0 as the default and selects nothing with k < 1);
          inf is allowed, nan is refused.
        - NA (either side not a number) fails the test and is counted, also for /epx/ and
          /omx/.
        - Arithmetic: x and y both integers: /ep/ compares |x - y| exactly with eps (checked
          subtraction; on overflow the f64 form decides). x, y and k integers: /om/ tests
          |x| <= |y|*k and |x|*k >= |y| on unsigned absolute values, an overflowing product
          deciding its half of the test. Otherwise f64 with pick's formulas
          (y - eps <= x <= y + eps; |y|/k <= |x| <= |y|*k). NaN fails /ep/ and /om/, so it
          passes /epx/ and /omx/.
        - Tests: big-ep and big-om (from pick, with pick's refs), filter-ep-om (labelled:
          defaults, constant y, /epx/ /omx/, eps = 0, y = 0, negative values), filter-ep-int
          (integers beyond 2^53 and near Int::MAX, same results with int128), errors. pick's
          eptest1-3 need computes.

  5   Bit filters /all/ /any/ /none/ /notall/. Commit.
        - Semantics: /all/ (|x| & |m|) == |m|; /any/ (|x| & |m|) != 0; /notall/ and /none/
          negate. Computed with unsigned_abs() and & on the unsigned type (Int::MIN has an
          absolute value; i64 and int128 builds agree). Mask 0: /all/ always, /any/ never.
        - A constant mask must be a non-negative integer (a float, a non-number or a negative
          constant is an option error). pick compares /all/ and /notall/ with the raw mask, so
          /all/-5 never holds there; a mask from a column (:NAME) is taken as |m| for all four
          operators, a difference from pick for negative column masks.
        - A value or column mask that is a number but not an integer (5.0, 1e3, an integer
          beyond Int) fails the test and is counted separately from NA, reported as
              pluk: @flag/all/5: 2 values not an integer (rows not kept)
          (pick truncates with int()). Non-numbers keep the NA count. Both also for /none/
          and /notall/.
        - Tests: big-strbit (from pick, with pick's ref), filter-bit (labelled: all four, mask
          0, negative values, column mask), SAM FLAG on sam.txt and sam.bam (@2/any/16,
          @2/none/4), filter-bit-nonint (counts and messages), filter-bit-errors.
