step13 notes: decisions and rationale for implementation choices.

  Decisions: step13.txt (decisions 1-11).


Item 1: basic and slicing operators

  Files: ops.rs (len lc uc rev rot13 substr head tail skip shed strim; the helpers
  int_operand, string1, slice2, clamp, substr_range), opt.rs (help).

  Strings are bytes (decision 1): len counts bytes, rev reverses bytes, lc and uc use
  make_ascii_lowercase/uppercase (only A-Z, a-z change), rot13 maps ASCII letters. This is
  what pick does, since Perl without decoding works on bytes and changes only ASCII case
  without a locale: the comparison with UTF-8 and Latin-1 input (Émile, café, NAÏVE,
  Latin-1 été) is identical.

  Shared rules: an NA operand gives NA (a string operator does not turn NA into the text
  NA); a count operand must be an integer (int_operand), otherwise NA (pick: Perl converts
  1.5 to 1 and fox to 0). A number used as a string is written as text first
  (Machine::into_bytes, with --num-perl as set).

  head tail skip shed clamp k to 0 .. length (pick's boxit) and slice in place
  (truncate, then drain the front), so no new allocation is needed for an owned string.

  substr follows Perl's substr($x, $i, $k): substr_range computes the byte range, a
  negative i counting from the end, a negative k leaving -k bytes off the end; a range
  partly outside the string is cut to the part inside; a range wholly beyond either end
  is undef in Perl (with a warning) and empty in pluk. Checked against Perl itself on 1734
  combinations (strings of length 0..5, i and k in -8..8): identical. The test
  string-substr keeps a smaller grid (lengths 0..3) as regression.

  strim s nx ny takes nx bytes from the start and ny from the end (negative counts are 0),
  empty if nothing remains (pick).

  Checked against pick (--num-perl): string-basic (data.txt names, floats as strings,
  slicing beyond the ends, negative counts; big.txt; UTF-8 and Latin-1 input) is identical.

  Tests: string-basic, string-substr, string-edge (non-integer counts, NA operands,
  negative counts). Help refs.


Item 2: padding and counting

  Files: ops.rs (ppl ppr zp nchar; the helper pad), opt.rs (help).

  pad() pops the width N and x and pads x with blanks (ppl at the back, ppr at the front)
  or zeros (zp, at the front) to N bytes; a longer x is unchanged. N must be a non-negative
  integer, otherwise NA (Perl's sprintf('%*s') left-aligns for a negative width; pick's zp
  computes a negative padding as none). zp pads the string, so -2 with width 4 is 00-2, as
  pick. Rust note: inserting at the front uses Vec::splice(0..0, repeat_n(fill, k)), which
  shifts the bytes once.

  nchar x c counts the non-overlapping occurrences of c in x with memchr::memmem::find_iter
  (memchr is already a dependency, since step7); for a single byte this is pick's count (a
  chop loop comparing characters); for a longer c pick always counts 0, pluk the
  occurrences (aaaa contains aa twice). An empty c counts 0.

  Checked against pick (--num-perl): string-pad (data.txt names, negative numbers with zp,
  floats with ppr, width 0 and smaller than the string, nchar of single characters;
  big.txt) is identical.

  Tests: string-pad, string-pad-edge (negative, float and non-number widths, overlapping
  candidates, empty c, NA). Help refs.


Item 3: joining

  Files: ops.rs (catall joinall join uie; join_values; Pops::All(min)), compute.rs (the
  stack check with the minimum), opt.rs (help).

  Pops::All now carries a minimum: the whole stack, which must hold at least that many
  values. addall and the other whole-stack operators have All(0); joinall has All(1), its
  separator (pick declares joinall with one required operand), so '::,joinall' is a stack
  underflow at compile time, like any other operator.

  join_values writes the values as text with a separator between them; an NA value or
  separator gives NA; no values give an empty string. catall joins the whole stack without
  separator; joinall pops the separator first and joins the rest; join x y j gives x j y
  (pick: "$x$j$y" from the stack order x y j). uie pushes x itself if it is not NA and not
  empty, otherwise y (decision 6; pick tests the length only).

  A testing pitfall, found here: the comparison helper used in these notes discarded
  stderr, so an invocation that both pick and pluk refuse compared as equal. The first
  join test had c::name:fx^:,join, where ':' starts a new (empty) column token; both
  programs rejected it. The helper now also requires pluk to succeed and to produce data;
  rerunning it on all 23 pick comparisons of step12 and step13 found no other such case.
  ^%3A is the constant ':'.

  Checked against pick (--num-perl): string-join (data.txt and big.txt: catall, joinall
  with a separator, join with ':' and '_', uie with an empty and a non-empty x, an empty
  stack for catall and a separator alone for joinall) is identical.

  Tests: string-join, string-join-edge (NA in each operator, empty x for uie, joinall
  underflow). Help refs.
