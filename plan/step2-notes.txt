
step2 notes: rationale for implementation choices.


Item 1: output_colnames, output_offset

  src/select.rs defines OutputSelection with the two arrays from the step file. from_names() checks
  each command line argument, looks it up in the ColumnNames dictionary (step1 item 6) and stores
  name and 0-based index. A name given again is skipped (its index is already present) and pick's
  message is printed once. The duplicate test is a linear search of output_offset, which is
  adequate for command-line-sized lists.

  Arguments that will change meaning later are rejected (leading '+', or containing ':' '@' '%');
  everything else is a plain name, including regex characters (COLSPEC.design.txt).

  Command line arguments as bytes. clap delivers the column arguments as OsString, the operating
  system's string type, which on Unix is an arbitrary byte sequence (like char *argv[]). main.rs
  converts them to Vec<u8> with into_vec(), from std::os::unix::ffi::OsStringExt. Using String
  instead would make clap reject arguments that are not valid UTF-8, while header names may well
  contain such bytes. into_vec() exists on Unix only; pluk, like pick, targets Unix systems.

  Timing of the check. As in pick, names are checked after the first line has been read, because
  the column names come from it. With empty input there is nothing to check against and pluk exits
  normally, as pick does (LineReader.is_empty).

  Errors are passed to main as std::io::Error of kind InvalidInput, for the same single-error-type
  reason as in step1 item 5.

  The temporary option --test-select prints output_colnames with output_offset.


Item 2: output, header line, -h

  src/output.rs defines RowWriter, created once from output_offset. write_header() writes the names
  of the selected columns ('_' as an empty name); write_row() writes the selected fields of a Row.
  B_print_header follows pick: on by default, off with -k, off with -h or -c (main.rs).

  clap's automatic -h is disabled (disable_help_flag) and --help is defined explicitly, so -h is
  free for "no header" as in pick.

  Without column names (and without -c or a --test-* output mode) pluk prints a short usage message
  to STDERR and exits with status 0, as pick does. This check is made before reading input.

  step1 output. The numbered line output is now behind --test-lineno (and --test-i). The step1 test
  invocations without column arguments were given --test-lineno; their outputs are unchanged.

  Efficiency.
    Each field is written with write_all() straight from the line buffer into the output BufWriter,
    with a TAB between fields. Each call is a bounds check plus a memcpy into the 128 KiB output
    buffer; the system call happens only when the buffer is full. The alternative -- assembling the
    output line in a separate Vec<u8> and writing that -- copies every byte twice and is not faster.

    Fast path: if the selection is all columns in their original order (as -A will produce), the
    line is written with a single write_all(). Not used with -O, because a padded short line lacks
    the TABs of its added empty fields.

    Measured on big.txt repeated to 1,000,000 rows (100 MB, 20 columns), output to /dev/null:
        cat                                   0.01 s
        pluk -c          (read, split only)   0.08 s
        pluk, all columns in order (fast)     0.08 s
        pluk, all columns, x first (20 calls) 0.14 s
        pluk id dna x                         0.09 s
        pick id dna x                         2.5  s
        pick, all columns                     3.0  s
    Reading and splitting dominate. Writing per field costs about 3 ns per field. A faster split
    (memchr, SIMD byte search) would be the next optimisation if needed.

  Comparison with pick. Output was compared with pick for 15 invocations (data.txt, big.txt, -h,
  -k, -kO12, -kO25, padding, -R, empty first name, duplicates, header-only input): identical.
  pick's own test o.sq-fib (plain names) is included with pick's reference output.


Item 3: -A, -x

  select.rs: the lookup of names (syntax check, dictionary lookup, unknown-name error) is factored
  out of item 1 into lookup(), which returns the indexes in the given order, duplicates included.
  The three ways of selecting use it:
    from_names()  the named columns, duplicates dropped with pick's message (item 1);
    all()         -A: all columns in input order; given names are checked but add nothing;
    complement()  -x: all columns in input order except the given ones.
  All three fill output_colnames and output_offset through from_offsets().

  Behaviour follows pick, checked against pick for 20 invocations and pick's own tests o.-A and o.-x:
    - -x alone outputs all columns; -x with -A behaves as -x.
    - Repeated names with -A or -x give no message (pick prints none there either).
    - Excluding all columns outputs empty lines, including the header line.
    - Unknown names are an error for both.
  pick drops the last header name for 'pick -A name name'; pluk outputs the full header (test A-dupnames).

  -A produces offsets 0..N-1, so it uses the whole-line fast path of item 2 (except with -O).
