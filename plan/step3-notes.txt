
step3 notes: rationale for implementation choices.


Item 1: why bespoke option parsing

  Steps 1 and 2 use clap. pick's command line interface has properties that a standard parser
  does not support, or supports only through workarounds. Three examples, from current and
  anticipated options:

  1  Bundling with attached arguments, including patterns. In -A4kO8/^# the option -A takes an
     optional number (4), k is a plain flag, O takes a required number (8), and / introduces a
     pattern (^#) that extends to the end of the word and may contain any character. The parser
     must know the argument shape of each option within a single word. clap supports bundled
     flags, but not an optional attached value followed by further flags, nor a '/' separator.

  2  Option names that carry data. The anticipated dictionary options (--kd-NAME/default=,
     --fd-NAME/..., --td^colname/... in plan/sketch) embed a user-chosen name and default in the
     option itself. They cannot be declared in a fixed option table; the parser must recognise a
     prefix and decompose the remainder.

  3  Order-dependent meaning. pick processes options from left to right, so 'pick --sam -O3' uses
     -O3 and 'pick -O3 --sam' uses -O12. clap collects values without their order; pluk currently
     gives an explicit -O priority (step2 item 4). A bespoke parser makes this a deliberate choice,
     either pick's order rule or a priority rule, rather than one imposed by the crate.

  A minor additional point: clap claims -h for help, which had to be disabled in step2 item 2,
  since pick uses -h for "no header".


Item 3: bespoke parser, clap removed

  src/opt.rs. parse() takes the arguments as bytes and returns Parsed: Run(Config), Help or
  Version; errors are returned as a String. parse_args() wraps it: it prints help, version or the
  error message (exit 1) and exits, so that parse() itself has no side effects and can be unit
  tested. Config keeps the field names of the clap version, so main.rs is nearly unchanged;
  columns is now Vec<Vec<u8>> directly (the into_vec() conversion moved from main.rs to opt.rs).

  Structure, as decided in item 2:
    - parse() walks the words; '--' ends the options, '-H' (a word of its own, as in pick) ends
      parsing with Help. A word starting with '--' goes to parse_long(), any other '-' word to
      parse_bundle().
    - parse_long() matches the whole word (after '--') against the known names with a byte-string
      match. Options with a value use the form --name=value, as pick does (--demux-buffer=N).
    - parse_bundle() scans character by character. A and O read an attached number (number_len,
      parse_number); '/' hands the rest of the word to parse_patterns().
    - Combination checks (-O needs -k, -R excludes -k) run once all options are known.
  Order rule: --sam and --sam-h set -k and -O12 at their position, so a later -O overrides them and
  an earlier one is overridden. This replaces the explicit -O priority of step2 item 4 and now
  agrees with pick; checked against pick for both orders (test opt-order-sam, existing sam-O3).

  Patterns: parse_patterns() splits /PAT, //PAT and /PAT1//PAT2, refuses an empty pattern or one
  containing '/', and %-decodes with pct_decode() (pick's urldecode: %XX with two hex digits,
  anything else kept). The patterns are stored in Config but not yet used (item 4).

  -A<N> is stored as insert_offset (i64) and not yet acted upon.

  Small differences from pick in this item:
    - A flag letter repeated in a bundle (-kk) is accepted; pick reports the second one as not
      parsed. Left-to-right scanning makes repetition harmless.
    - -O without digits gives "-O<N> requires an attached number N, e.g. -O12" instead of pick's
      "Option string not fully parsed: -O remains".
    - An empty pattern is refused. In pick, -// sets an empty pass pattern that matches every line.
    - --version prints "pluk <version>"; --help and -H print a one-line placeholder until item 5.

  Test changes. --test-i N became --test-i=N (12 invocations in test/Makefile), as a '--' option
  now takes its value in the same word. Output is unchanged. All other invocations run unchanged.
  New tests: opt-bundle, opt-A-neg, opt-dashdash, opt-col-dash (a dash word after the first column
  name is a column name, as in pick), opt-order-sam, opt-errors; and unit tests in opt.rs.


Item 4: -/PAT and -//PAT filtering, --test-comment retired

  Crate: regex (regex::bytes), the standard Rust regex crate; it brings regex-automata,
  regex-syntax, aho-corasick and memchr as dependencies. The bytes variant matches on &[u8], so
  lines that are not valid UTF-8 are handled.

  io.rs:
    - InputSettings.pat_purge and pat_pass hold the compiled patterns; skip_comment_preamble and
      the in_preamble flag are gone.
    - accept_line() tests every line, the header line included, before splitting, as in pick:
      first whether to pass it through (-//PAT, or an '@' line with --sam-h), then whether to skip
      it (-/PAT, or an '@' line with --sam). A line matching both is passed through, as in pick.
      Both count as skipped; pass-through lines are also counted as such. The SAM '@' prefix test
      of step2 item 4 is kept, so a user pattern applies in addition to it. In pick --sam and -/PAT
      share one pattern variable, and 'pick --sam -/PAT' no longer skips '@' lines.
    - compile_pattern() builds the regex with Unicode mode off. Matching is then on bytes, as in
      Perl without 'use utf8': '.' matches any byte except newline; \w \d \s and (?i) are
      ASCII-only. A literal non-ASCII character in the pattern still matches its UTF-8 bytes.
      The crate takes the pattern as a str, so a pattern that is not valid UTF-8 after %-decoding
      (e.g. %FF) is refused; such bytes can be written as \xFF in the pattern.
    - Lines are matched without their trailing newline. Perl matched with it, but '$' in Perl
      matches before a final newline, so ordinary patterns behave the same.
  main.rs compiles the patterns before reading input; a regex syntax error is reported as an
  option error (exit 1). --test-counts now also prints passthrough= when -//PAT is given.

  Rust regex syntax differs from Perl's mainly in lacking backreferences and lookaround; such a
  pattern is a syntax error.

  Cost, on big.txt repeated to 1,000,000 rows (100 MB), pluk -A to /dev/null:
      no pattern               0.085 s
      -/^#zz                   0.096 s
      -/zzz                    0.093 s
      -/(?i)ACGTACGTTT         0.114 s
      -//^#zz -/xyz            0.113 s

  Comparison with pick for 18 invocations: identical, except where expected: pick has no gzip
  input from STDIN; the --sam/-/PAT interaction above; pick's sequence length lookup message
  (deferred); and the step1 duplicate-name message when the header line is purged.

  Tests. --test-comment and --tc are removed. Their invocations are kept, not run, in the new
  target runretired of test/Makefile. In runtestopt they are replaced by the same invocations
  with -/^# (with -/^%23 for the former --tc alias test, exercising %-decoding), writing the same
  .test files and compared against the unchanged .ref files. The exception is tc-midfile: --tc
  only skipped leading '#' lines, -/^# skips them anywhere, so it is replaced by pat-midfile;
  o.tc-midfile.ref is listed in RETIRED_REFS and excluded from rundiff.
  New tests: pat-* (purge, pass, both, pass before purge, -c with pass-through, regex flags,
  purged header, byte matching, \xHH escapes, gzip, with --sam and --sam-h, pattern errors).


Item 5: -H and --help

  opt.rs holds the text in a constant HELP, printed by print_help(); -H and --help both lead to
  Parsed::Help and exit 0 before input is read. -H must be a word of its own, as in pick (-kH is
  an option error).

  Layout: usage line, one-line description, then one line per option in the order of the step
  file, with the argument form (-A<N>, -O<N>, -/<pat>) in a fixed-width first column. -A and -A<N>
  have separate lines since they differ in meaning. -H/--help and --version close the list, and
  two final lines state the general rules: short options combine, options act from left to
  right, '/' in a pattern is written %2F. Column specification syntax is not explained yet.
  -l and -z, and the --test options, are not listed.

  Tests: help, help-long (identical output), help-bundle.
