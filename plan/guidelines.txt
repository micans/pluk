
# Project development

  Follow the steps in files step1.txt, step2.txt and so on. A secondary impromptu level may be introduced later
  if necessary, e.g. step3b.txt would follow step3.txt. These steps are part of the repository.
  Steps often have a set of logically related items. Sentences starting with 'Commit' indicates
  to first test and then commit at that point.

  Before each commit, copy suitable tests from the pick test suite and add it to the pluk test suite,
  or write a new test if no such test can be found. Only add tests that are suitable for the
  current step or the functionality supplied by the corresponding state of pluk.
  Use either data.txt or big.txt as input for tests except those that require SAM or BAM input.
  The pluk test suite lives in pluk/test/ and follows pick/test: a Makefile runs invocations, output is compared
  against .ref files. Unit tests of internal functions use cargo test.
  Make sure all tests pass at each commit.

  Options that start with --test (e.g. --test-comment) will be removed again. Tests for such options
  will need to be grouped separately. When an option is removed, corresponding tests should not
  be removed but rather simply omitted from running.  Document when this happens.

  Develop each step in a branch with the same name. Thus, step1.txt will be developed in branch step1.

  Merging branches to main and pushing to origin will be done by me.

  The collection of steps is the plan. The plan is important documentation. It may be refined while we are executing it.
  The full plan is not yet available.  For example, after step4.txt (once it is present) is implemented, I may decide
  that a step was missing, and we will go back to implement step3b on top of the code that forms step3.

  Before starting a step, confirm. If you can improve the step, its items, or the order of steps or items currently
  available, suggest those improvements.  The improvements will be added to the step file(s). We may use a file
  step-<N>-context.txt to memorise some context or discussion that does not fit naturally in either step<N>.txt or
  step<N>-notes.txt.

  For the foreseeable future pluk's interface will be exactly the same as pick's. More esoteric pick features,
  which will arrive very late in the step sequence, may be rethought at that time.
  Intended differences from pick are decided explicitly and listed here, with a pointer to the design file:
    - regex column names are introduced by a leading '+' and match the whole name (COLSPEC.design.txt, 1).
    - -u (make duplicate input column names unique) and the duplicate check on input names (step1 item 6).
    - -R cannot be combined with -k (step1-context.txt).
    - In -/PAT and -//PAT a literal '/' must be written as %2F, and an empty pattern is refused
      (step3.txt item 2, step3-notes.txt item 3).
    - Repeated flag letters in an option bundle are accepted (step3-notes.txt item 3).
    - -/PAT and -//PAT use Rust regex syntax (no backreferences or lookaround), matching on bytes
      (step3-notes.txt item 4).
      This holds for every pluk regex; Perl's \K and look-around (?= ?! ?<= ?<!), used
      prominently in pick's manual, are not available; capture-group workarounds and their
      one limitation (overlapping context in global substitutions) are recorded in
      step14-notes.txt ('Regex: \K and look-around').
    - --sam and --sam-h keep skipping or passing '@' lines when -/PAT or -//PAT is also given
      (step3-notes.txt item 4).
    - Numeric filters: a value that is not a number (empty, 'fox', '0x10', ' 4') fails the
      comparison and is counted (pick: such values count as 0); a non-numeric constant is an
      error; bit filters do not truncate floats (step7.txt, NUMERIC.design.txt). In a filter
      VALUE, ':' and '^' are recognised before %-decoding (%3Ax is the literal ':x')
      (step7-notes.txt item 1).
    - Regex filters (~ /~) use the regex crate's dialect as -/PAT and refuse an empty pattern;
      with :NAME the other column's value is matched as a fixed string, not as a regex
      (step7.txt item 2).
    - Dictionary filters (~isin~ ~hasval~ ...): VALUE cannot start with ':' or '^'; the ~v
      argument of ~hasval~ must be separated by '~' and cannot contain a further '/' or '~'
      (%2F, %7E); a leading ':' in it is reserved; an unknown dictionary is reported once the
      header has been read (step7.txt item 3).
    - /ep/ /om/ bands: optional, separated by '/', a number with eps >= 0 and k >= 1 (pick: 0
      or empty means the default; k < 1 selects nothing); eps = 0 is exact equality. A
      non-number fails /epx/ and /omx/ too. Integer operands are compared exactly
      (step7.txt item 4).
    - Bit filters: a negative constant mask is refused; a mask from a column is used as |m| by
      all four operators (pick: /all/ /notall/ use the raw mask); a non-integer value is not
      truncated but fails and is counted separately (step7.txt item 5).
    - -k ranges: a range that selects no column is an error, and a multiplier of 0 (S-E*0) is
      refused (pick: empty or repeated selection) (step8-notes.txt item 2).
    - Additions without a pick counterpart: multi-column filter handles (lists, + regexes, -k
      ranges; the test must hold for every column), unary predicates /ISINT /NOTINT /ISNUM
      /NOTNUM (step8.txt items 3 and 4).
    - Assertions: @@assert@ (before computes) is new; a failed assertion ends pluk with exit
      status 1 (pick: 255, Perl die) and the message 'assertion A failed: column C value [V]
      at line N'. --assert-other diverts failing rows instead (step9.txt item 2).
    - Output files (--other, --assert-other, --demux): never opened through a shell; --other
      also receives rows rejected by @@ filters; --assert-other covers @@assert@ too and
      combines with @ filters (pick refuses them); the pass-through preamble is written to every
      output file; with -c the files keep their header, and without column arguments get
      whole rows; demux file names are restricted (no empty, absolute, '.' or '..' parts),
      --demux-dir sets their directory, too many open files is an error, the tally has no
      LastFlush column, --demux-buffer has no effect, -c with --demux is refused (step9.txt).
    - Computes (COMPUTE.design.txt): a value that is not a number gives NA in numeric
      operators (pick: 0), written as NA; floats are written round-trip (0.1+0.2 is
      0.30000000000000004; --num-perl writes them as Perl, approximately, step10-notes.txt
      item 4); unnamed computes are PLUKAAAAA, ... (pick: PICKAAAAA); a regex operand must be
      a constant; integer overflow goes to a float directly (Perl first uses unsigned 64-bit
      integers); rows rejected by @@ filters have empty computed columns in --other.
    - In-place computes (INPLACE.design.txt): an input column can be redefined once (pick:
      any number of times); a list NAME cannot create new columns, a repeated column in a
      map NAME is applied once; -A<N> cannot be combined with -x; renaming forms
      (P/SPEC/S), capture-group naming and --A=NAME are not implemented (yet).
    - -K cannot be combined with --sam or --sam-h (step11-notes.txt item 5).
    - Arithmetic (step12.txt): division by zero gives inf or nan (div) or NA (idiv, mod)
      where pick dies; a float given to idiv, mod or ipow is NA (pick truncates); ipow
      overflow is NA; sign of nan is nan (pick: 0); /ISNUM fails on nan; log, sqrt of 0 or
      negative values give -inf or nan (pick dies); log10, log2 and tan are computed
      directly (pick: log(x)/log(10), sin/cos), which can differ in the last digit;
      meanall, hmeanall, gmeanall, maxall and minall of an empty stack are NA (pick: 0, 0,
      1, -DBL_MAX, DBL_MAX); maxall(-inf) is -inf; gmeanall is computed from logarithms
      (pick multiplies; last digits can differ, pluk cannot overflow); frac, pct, pml
      divide by zero to inf or nan (pick dies); their N must be an integer 0..1000; rand
      uses its own generator, seeded from the clock or with --seed=N (pick has no seed).
    - String operators (step13.txt): an NA operand gives NA, and a count that is not an
      integer is NA (pick: Perl converts); substr outside the string is empty (Perl:
      undef and a warning); a negative padding width is NA (Perl left-aligns); nchar
      counts substring occurrences (pick: single characters only); uie treats NA as empty;
      joining an NA gives NA; a constant fmtall format whose # count does not match the
      values is an error before input is read, a format from a column gives NA per row
      (pick reports an error per row).
    - Regex operators (step14.txt): patterns must be constants (pick: also columns);
      reqm and sprintf are not implemented (deferred.txt); lazy patterns that can match
      empty (a*?) iterate differently from Perl in the global operators; \Q...\E works in
      every pluk regex (-/PAT, filters, '+' column regexes, compute operators; pick: only
      in filters and computes).
    - Dictionary operators (step15.txt): the dictionary operand of map and dord is a
      constant; map's __EXIT__ ends the run with the line number; dord numbers the first
      appearance across merged sources (pick: line number per file, the last occurrence
      winning) and gives NA for an absent key (pick: ~0); seqlen has no order.
    - test gives NA where a filter would reject a non-number (pick: 0 or 1 on Perl's
      conversion); ~hasval~ and the predicates are refused in test; ifelse with an NA
      condition gives NA; a fetch of a constant register name that no earlier save stores
      is an error before input is read (pick: an error per row and NA).
    - Time operators: ttu needs exactly a number and a unit (pick also matches the end of
      a longer value) and gives NA otherwise (pick: 0), a constant that is not a time unit
      is an error before input is read; rttu rounds a float to the nearest second (pick
      truncates); todate takes integers (a float is NA).
    - Bit operators take the absolute value of both operands (pick: of y only; Perl treats
      a negative x as unsigned 64-bit, -1 bitor 0 is 18446744073709551615), a float
      (including 3.0) or a non-number is NA (pick: Perl's conversion, fox is 0); bitoff
      is x & !|y|; bitlsh gives NA when the result does not fit Int (pick: bits lost, 0
      for a shift of 64 or more); bitrsh by Int's width or more gives 0, as pick.
    - Radix: tobin tohex tooct write a negative integer as sign and magnitude (-ff; pick:
      64-bit two's complement) and give NA for a float (pick: Perl's int). binto hexto
      octto parse the whole value strictly: an optional minus (so that -ff reads back),
      an optional prefix matching the operator (0b,
      0x, 0o, either case; pick's binto refuses 0b, its octto also reads 0x and 0b, its
      hexto also reads a bare x), digits with single _ between digits (Perl also allows a
      leading _ or one after the prefix); anything else, including a plus, whitespace, the
      empty string or a value beyond Int, is NA (Perl: stops at the first invalid
      character, 0 for nothing read).
    - -z encodes only % : ^ , / ~ = @ + and white space or control bytes (pick: all but
      [A-Za-z0-9_]); -zz writes one value per line (pick: one line); the table without
      arguments goes to stdout (pick: stderr); -zzz is an error (pick: encodes).
    - -l lists by category in --help order (pick: alphabetically); a TERM is a category
      name or a fixed substring of operator names (pick: a regex on section tags and
      names); the filter operators are listed too (category filter); no match is exit 1;
      -ll is not supported.
    - -q has one level (-qq is -q) and silences every message that is not an error; -v
      and -d are not taken over. -E<N> counts the rows that pass the filters (stdout or
      --demux, the -c count), not those diverted to --other or --assert-other.
    - --progress counts input data rows, rejected or not, and also with -c (pick counts
      at the output, so rejected rows give no dot, and -c gives no progress).
      --idx-list --name-list --idx-map cannot be combined with each other, -c, --demux,
      --other or --assert-other; --A=NAME must name an input column (pick: any output
      column).
    - SAM normal form: a rule that would leave an empty CIGAR is not applied (pick turns a
      CIGAR 5D into an empty CIGAR and moves POS); --sam-nonf requires --sam or --sam-h.
    - SAM operators (step17) need --sam or --sam-h (compile-time error). Values that cannot be
      computed are NA and the row is kept, with counts at the end (pick discards the row
      silently or computes from missing data): unmapped records (FLAG 0x4, RNAME or CIGAR
      '*'), a CIGAR or POS that is not valid, an unknown reference length (pick: 0). An X
      operation from the input is aligned (pick: exterior, as its context marker); the CIGAR
      trails never overlap (pick: a CIGAR of only S H D N I counts twice). aln_nedit with a
      NM:i value that is not a non-negative integer is NA (pick: 0). suv and input_cigar are
      not taken over.
    - SAM reference and parts (step18): the reference sequence comes only from --sam/FILE
      or --sam-h/FILE (pick: also the first fasta dictionary given); an operator that needs
      it without them is a compile-time error (pick: rows discarded silently); an RNAME not
      in SAMFA ends the run only when an operator needs the reference (pick: whenever a
      sequence is needed). ref_ and qry_ parts that cannot be computed are NA (pick: '*'),
      including a matched part that ends past the reference (pick: partial substrings).
      Alignment strings: an X operation is compared (| or x; pick draws '.'); P draws
      nothing (pick stops the alignment there); a CIGAR past the reference end gives NA
      (pick: a message and the partial strings); only QUAL '*' is replaced by '!' or '.'
      (pick: any QUAL shorter than 2), another QUAL that does not fit SEQ is NA;
      --sam-qlt-sim leaves a qry_qual of '*' as it is (pick: ','); --sam-aln-mrk,
      --sam-qlt-sim and --sam-aln-prefix require --sam or --sam-h.
      aln_posinfo compares = and X as M (pick stops at them with a message), ignores case
      (all letters upper-cased, U as T; pick upper-cases only acgtu and reports n against N),
      walks past P (pick stops), gives NA past the reference end (pick checks M only) and
      for an n that is not a non-negative integer. patchiness and patchiness2 give NA for a
      character outside their table, a newline included (pick dies, or skips a newline),
      and for a window that is not a non-negative integer.
    - SAM context extension (step19, SAMVIEW.design.txt section 3): --sam-aln-xy extends
      only as far as needed to include X..Y (pick: to the reference ends in most cases,
      survey 8.1, 8.2); without --sam-aln-context the context is 0 (pick: 10000); with
      both, the larger budget per side; a soft clip behind a hard clip is used and H stays
      outermost (pick writes D before H); without a reference length the right side is not
      extended (counted); unmapped records and invalid CIGARs or POS are not rewritten.
      aln_nedit_pia and aln_nedit_piu count only x - ~ (and =) columns: dangling columns
      ` _ . are never edits (pick counts ` and .); aln_posinfo skips context (pick stops at
      the first X). X,Y are positive integers, X <= Y.
    - SAM sequence fill (SAMSEQ.design.txt): a SEQ '*' is filled from an earlier row of the
      same read and segment whose part of the read contains the needed part (hard clips
      respected), whatever the rows between; the cache is updated before every filter, so
      a primary removed by @@ still supplies its secondaries (pick: the previous row only,
      only rows that pass @@, no hard clips, no segments). A row that cannot be filled is
      skipped (default) or ends the run (--sam-seqmiss=exit) (pick: discarded silently); a
      SEQ that does not fit its CIGAR gives NA for qry_seq qry_qual (pick: the SEQ).
    - cgsum cgmax cgcount: a CIGAR that does not parse (also the empty string and lower-case
      operations, which pick's case-insensitive match accepts) is NA (pick: a message and the
      partial result, 0 for nothing).
    - BAM input is accepted by --sam and --sam-h, recognised from its content; there are no --bam
      options (pick has no BAM support). A header text without @SQ lines gets @SQ lines from the
      binary reference list; @SQ lines that differ from that list are an error (step6.txt).
    - Dictionaries (step4.txt, step4-notes.txt): --td^key/default order (pick: /default^key);
      %-decoded defaults; no named table dictionaries and no tmap; repeated NAME merges with a
      diagnostic, __EXIT__ sticky; only --sam/f.fasta sets the SAM reference; SAMFA and seqlen reserved; @SQ lines after
      the first alignment line are not used for seqlen (warning);
      fasta '>' without identifier, repeated identifiers and data before the first '>' are errors; --cd ignores empty
      pairs and refuses a pair with more than one ':'; --td refuses a '^' in DEFAULT (catches
      pick's order) and a repeated column name in the table header.

# Coding guidelines

  Write robust code. Favour simplicity and readability over sophistication or code that derives its power from
  behind-the-scenes implicit transformations or powerful macro features.  If sophisticated and opaque code is the better
  solution, make a comprehensive note in the file step<N>-notes.txt.

  Add comments to help the programmer/maintainer, but keep it to a minimum. Write comments in a neutral and formal voice.

  Decompose pluk functionality into source files. Add rationales for choices first in discussions, then in step<N>-notes.txt.

  Only import well-established creates, err towards fewer crates rather than more. Discuss where needed before starting
  a step.

  For argument parsing initially use a standard crate. We will later change to bespoke argument parsing.
  It will probably be necessary to change some of the test invocations when that happens.


# Core compute logic.

  The core compute logic will probably be similar to pick but is up for discussion. I envision using a similar
  stack-based approach for computes, tied to a bytecode interpreter. For the bytecode interpreter type
  inference, conversion and coercion will need to be fleshed out. I want to postpone this discussion until some of the
  input and output code (for now steps 1 and 2) has been written.
