step8 notes: decisions and rationale for implementation choices.


Decisions taken before implementation

  Outcome of the discussion is in step8.txt; column specification rules in COLSPEC.design.txt
  sections 3-5. Points of rationale:

    - 'All' semantics without expansion into separate filters: -o would otherwise turn
      @foo:bar/gt/0 into 'any', silently.
    - 'Any' deferred: not the negation of 'all' when values can be NA.
    - /ISNUM rather than /ISFLOAT: an integer is a valid float operand (promotion), so a strict
      'is float' test would reject a measurement column containing '3'. /ISFLOAT may come back
      with a defined meaning if needed.
    - Predicates in uppercase, trailing: no collision with [a-z]{2,19} operator tokens; '/~' is
      taken by the regex operator, hence NOTINT and NOTNUM rather than a negating prefix.
    - Assertions before filters within a stage: an integrity check should see every row that
      reaches the stage, not only the rows the filters keep (pick: asserts after computes and
      before @ filters).
    - pick's parse_range accepts a range that selects nothing; pluk refuses it, following the
      rule that every element of a column specification selects at least one column.


Item 1: column specifications for output selection

  Files: src/colspec.rs (new), opt.rs (column arguments parsed into ColSpec, -F, help),
  select.rs (lookup via ColSpec::expand), main.rs (mod colspec).

  colspec::parse() runs during option parsing: the argument is split on ':', each element is
  either Element::Name (%-decoded) or, with a leading '+' on the raw element,
  Element::Regex. A regex is %-decoded, compiled once as given (so that the regex crate's
  message shows the user's pattern) and once anchored as \A(?:re)\z, which matches the whole
  name and keeps the user's group 1 as group 1. Regex errors are therefore option errors
  before input is read. An argument containing '::' or ':=' is a compute (not yet supported).

  ColSpec::expand() runs after the header: names are looked up, regexes are matched against
  all column names in header order; every element must select a column. Duplicates are kept;
  OutputSelection::from_names removes them with pick's message, as before. The label and
  kind arguments produce pick's message forms ("(Output) handle [x] in output ..."), so that
  filters (item 3) can reuse expand() with (Select)/(Preselect). A plain name that is not
  found and contains one of [({\*?^$.| gets a hint: '-- a regex column name starts with
  '+', e.g. +num(\d) --'.

  Capture group 1: pick uses it only to name the new columns of a compute handle; plain
  output selection keeps the original names (checked: pick 'num(\d)' outputs num1 num2 num4,
  pick 'num(\d)'::__ outputs columns 1 2 4). COLSPEC.design.txt section 1 said the output
  column was renamed; corrected. Renaming will come with compute handles.

  '@' inside a name (a@b) is now accepted, as pick (only a leading '@' makes a filter); '%'
  is decoded. -F is accepted without effect.

  Checked against pick (with equivalent unanchored regexes on pick's side): lists, regexes,
  combinations, duplicates, -x and -A with regexes, -k with lists give identical output.

  Tests: colspec (labelled invocations), colspec-x-A-k, colspec-decode (%3A, %2B, '@' in a
  name, \+ in a regex), colspec-errors (option errors: empty regex, syntax, look-behind,
  computes), colspec-unknown (no match, empty element, the hint, anchoring). sel-unsupported
  reduced to @assert@, '::' and ':='. Help refs updated. Unit tests in colspec.rs.


Item 2: -k ranges

  Files: src/colspec.rs (Range, parse_range, Range::indexes), opt.rs (parse(arg, config.k),
  help).

  Syntax as pick's parse_range, recognised on the raw element only with -k (also implied by
  --sam): [O+]S-[E][*M] gives the 1-based columns O + i*M for i = S..E; without E up to the
  last column. A single number N is not a range but the plain name N, as pick: under -k the
  names are 1..N, so '007' is an unknown name in both, while inside a range numbers are
  numeric ('1-02' is columns 1 and 2). Without -k range syntax is a plain name ('3-5' can be
  a column name).

  The syntax is matched with a regex compiled once (std::sync::LazyLock: a static that is
  initialised on first use; the C analogue is a function-local static with an init flag, but
  thread-safe). It uses [0-9], not \d: regex::bytes has Unicode mode on by default, where \d
  also matches other digits such as U+0663, which would then fail to parse as usize.

  Expansion (Range::indexes): i runs from S to E (E defaults to the number of columns); since
  M >= 1 the column number increases with i, so the loop stops at the first column beyond
  the last, and a huge E costs nothing. Column 0 (S = 0, no offset) and columns beyond the
  last are dropped with pick's message '-- range expansion produced some indexes out of range
  (now dropped)'. Overflow in O + i*M counts as beyond the last column.

  Differences from pick: a range that selects no column (5-3, 14-20 on 13 columns) is an
  error, following the rule that every element selects a column (pick outputs empty rows);
  S-E*0 is refused at option parsing (pick repeats column O, or selects nothing); a number
  too large for usize is an option error.

  Checked against pick: 3-5, 11-, 2+1-3, 1-5*2, 2+1-3*4, 3:5-7:1, 12-15, 0-2, 0+0-2, 1-02:2,
  -x 2-12, --sam 1-4:10- give identical output, including the out-of-range message.

  Tests: colspec-range (labelled; includes a regex in the same list), colspec-range-msg
  (dropped indexes), colspec-range-other (-x, --sam, a range without -k is a name),
  colspec-range-errors (empty range, unknown number, 007, multiplier 0, number too large,
  column 0). Help refs updated. Unit tests in colspec.rs (ranges).


Item 3: multi-column filter handles

  Files: src/filter.rs (FilterSpec.handle: ColSpec, Filter.columns, Outcome, accept/test,
  report), opt.rs (parse_filter(arg, config.k), help).

  Parsing. The NAME part of a filter is parsed with colspec::parse (so '+' regexes, ':' lists
  and, with -k, ranges), after find_operator() has split the argument; '/', '~' and '=' in a
  regex are written %2F %7E %3D as before, ':' as %3A. Errors in the handle are prefixed with
  the whole filter argument ('[@+/gt/3]: [+]: empty regex after '+''). The :NAME operand is
  also parsed with colspec::parse and must be a single plain name.

  Compilation. The handle is expanded with ColSpec::expand using pick's labels
  ((Select)/(Preselect) handle [x] in select/preselect ...); duplicates are removed, keeping
  the first position.

  Evaluation. Filter::test(field, row) evaluates one column and returns an Outcome (Pass,
  Fail, NotNumber, NotInteger); Filter::accept loops over the columns and stops at the first
  that does not pass, counting its reason. Counts are therefore per row: a row with two
  non-numbers counts once, and a row whose first column fails normally is not counted even
  if a later column is not a number. The end-of-run message keeps its per-value wording for
  single-column filters and says '... N rows with a value not a number (not kept)' otherwise.
  Rust note: test() takes &self and accept() takes &mut self; the counters are updated only
  in accept(), so the per-operator code needs no mutable access.

  -o and -s combine a multi-column filter as a unit: filter-multi-or shows -o with
  @fib:fib2/gt/30 against the same test written as two filters (Inky, fib 34 and fib2 21,
  passes the latter only).

  Checked against pick, which has no multi-column handles, by writing the columns as
  separate ANDed filters: lists, regexes, regex + list, @@ with a string operator, :NAME
  operand, /ep/, and -k ranges (stdout) give identical output.

  Tests: filter-multi (labelled), filter-multi-k (ranges, with the header line as data and
  its NA count), filter-multi-or, filter-multi-na, filter-multi-nonint (both counts),
  filter-multi-errors (no match, unknown name in a list, list/regex/range after ':', empty
  element, compute). filter-errors: '@+x/gt/3' (formerly 'not yet supported') replaced by
  '@+/gt/3' (empty regex). Help refs updated. Unit tests in filter.rs (parsing_handles,
  extended error cases).


Item 4: /ISINT /NOTINT /ISNUM /NOTNUM

  Files: src/filter.rs (Op::Pred(Pred, negated), PREDICATES, find_predicate,
  parse_predicate, Filter::predicate), opt.rs (help).

  Parsing. find_operator() is tried first, unchanged: a lowercase /xx/ token, else the first
  '=' or '~'. Only when it finds nothing is find_predicate() tried: the argument must end in
  /UPPERCASE. So NAME contains no '=' or '~', '@x/gt/ISINT' is /gt/ with the constant ISINT
  (an error: not a number), and '@x~a/ISINT' is the regex operator with the value 'a/ISINT'
  (an error: '/' must be %2F). The rule 'the first operator ends NAME' is kept. An unknown
  uppercase token is an error listing the known predicates; lowercase /isint is not a
  predicate ('Filter invalid', whose message now mentions @NAME/PREDICATE). The handle is a
  column specification, so @@+foo.*/ISNUM tests every foo column.

  Evaluation. Filter::predicate() uses parse_num: ISINT holds for I (integer syntax that fits
  Int), ISNUM for I or F (so 1e3, inf and nan are numbers). An integer beyond Int is F: not
  ISINT, but ISNUM; between i64 and i128 the two builds differ, so the tests use a 42-digit
  integer. Predicates never count NA. The 'did you want :x' hint is skipped for the empty
  constant of a predicate.

  pick has no predicates, so there is nothing to compare against; the semantics follow
  parse_num, which is tested against the number syntax in num.rs.

  Tests: filter-pred (all four, @@, a range of number syntaxes and non-numbers),
  filter-pred-multi (regex, list and regex alternation handles), filter-pred-other (SAM FLAG,
  -o with another filter), filter-pred-errors. filter-errors: the 'Filter invalid' message
  changed. Help refs updated. Unit tests in filter.rs (parsing_predicates, predicates).
