step7 notes: decisions and rationale for implementation choices.


Decisions taken before implementation

  pick, for reference (parse_spec, compile_select, %sel_opdefinitions, main loop):
    - Filters are mixed with column names in the argument list and recognised by their form.
    - @NAME OP VALUE: the first operator occurrence ends NAME (a '/', '~' or '=' in a name must
      be %-encoded). VALUE is %-decoded; :NAME is another column; a leading ^ forces a literal.
      /ep/ and /om/ take an optional extra argument (defaults $::EPSILON 0.0001, $::OOM 2).
    - @@ filters are applied before computes (input column names); @ filters after computes.
      AND by default; -o ORs @ filters, -s ORs @@ filters. A constant equal to a column name
      gives a hint ("did you want :x").
    - Numeric operators are Perl's: '', 'fox' and '0x10' compare as 0 (with a Perl warning),
      ' 4' as 4; a non-numeric constant (@x/gt/abc) is 0. String operators compare bytes.
      Bit operators use abs(int(x)): 5.9 is 5, -3 is 3.

  pluk:
    - Same argument structure; computes recognised and refused for now.
    - :NAME implemented in item 1 (column names are resolved once the header is read).
    - @ and @@ both implemented with -o and -s, @@ evaluated first; the slot for computes lies
      between them.
    - Numeric values per NUMERIC.design.txt: not a number -> NA -> the comparison fails, counted
      and reported at the end. This differs from pick for empty fields, which are common in
      sparse tables (@x/lt/5 keeps empty fields in pick, not in pluk; @x/ne/5 keeps 'fox' in
      pick, not in pluk). A non-numeric constant is an error at option parsing.
    - Number syntax: integer syntax that fits Int -> I; else whatever Rust's f64 parser accepts
      -> F (no surrounding whitespace, no hex; inf and nan with IEEE semantics, so nan fails
      every comparison except /ne/); an integer too large for Int -> F.
    - Bit filters: abs() as pick; a float value fails and is counted (no implicit f -> i).
    - Regex filters (~ /~): the regex crate's dialect, as for -/PAT; ~ matches anywhere.


Item 1: @ and @@ filters, numeric and string comparisons

  Files: src/num.rs and src/filter.rs (new); opt.rs (trailing arguments, -o, -s, help), main.rs
  (compile after the header, keep() in the -c and output loops, end-of-run report), names.rs
  (joined(), now shared with select.rs), Cargo.toml (feature int128), Makefile (test-int128).

  num.rs. The Int alias (i64, i128 with --features int128), Num { I, F }, parse_num() and the
  comparison dispatcher compare() over cmp_ii / cmp_ff, as NUMERIC.design.txt. Integer syntax
  is checked first ([+-]digits) so that '1e3' and '5.' are F; an integer that does not fit Int
  falls through to the f64 parser and becomes F.

  Argument parsing (opt.rs, filter::parse_filter). Every trailing argument starting with '@' is
  a filter, the others are column names, in any order (as pick). @@ before @, and @assert@ is
  refused as not yet supported. find_operator() follows pick's two forms: the first token
  [/~][a-z]{2,19}[/~] ends NAME (an unknown token is an error, as pick: "unrecognised
  operator"); otherwise the first '=' or '~', with a preceding '/'. VALUE extends to the next
  '/' or '~'; anything after it is an extra argument, refused for these operators with a hint to
  write %2F or %7E. All operators of pick are known; those of later items give "not yet
  supported". Numeric constants are parsed here, so a non-numeric constant is an option error
  before input is read. Syntax errors are option errors (no 'pluk:' prefix, exit 1).
  Difference from pick: ':' (column) and '^' (literal) are tested on the raw VALUE, before
  %-decoding, so %3Ax is the literal ':x' (pick decodes first, making it a column reference).
  This follows the rule for '+' in COLSPEC.design.txt.

  Compilation (Filters::compile, after the header). Column names resolved with pick's messages
  ((Select) / (Preselect) / (Indirection select) / (Indirection preselect) handle [x] in ... does
  not reference a known entity among ...). The hint "You used x (a column handle) as a constant
  ..., did you want :x?" as pick, except (a) for a constant given as ^VALUE, which is explicitly
  literal, and (b) for a number with a numeric operator: with -k every column is named by a
  number and pick gives the hint for every numeric constant. With empty input nothing is
  compiled.

  Evaluation (Filters::keep). @@ filters first, then @ filters (computes will go in between);
  AND within a stage, OR with -s (@@) or -o (@); evaluation stops at the first filter that
  decides (pick evaluates all). Numeric: both sides parsed per row with parse_num (no cache yet;
  it comes with computes); NA on either side fails the comparison and is counted per filter.
  NaN satisfies only /ne/ (IEEE). String: byte comparison (Vec/slice Ord), as Perl without
  locale. Because evaluation stops early, a filter counts the non-numeric values among the rows
  on which it was evaluated. Report at the end, per filter with a non-zero count:
      pluk: @x/lt/5: 3 values not a number (rows not kept)
  The header line is not filtered; with -k it is a data row (and 'name' is not a number). -c
  counts the rows kept. Pass-through lines are not filtered. The temporary --test-lineno and
  --test-i outputs are not filtered.

  Checked against pick: the same invocations (strcmp, big-or, big-and, filter-num, -str,
  -column, -or, -count, -k, -int, -int-eq, -sam) give identical output; strcmp and big-or
  equal pick's own .ref files. The tests filter-na and filter-ne show the agreed difference
  (pick keeps '', 'fox', '0x10' as 0 and ' 4' as 4).

  Speed: 1,000,000 SAM lines, pluk --sam -c 0.28 s without filter, 0.26-0.27 s with one or two
  filters (pick --sam -c @@4/gt/500000: 9.5 s).

  Tests: strcmp and big-or (from pick, with pick's refs), big-and, filter-num, filter-str
  (each invocation labelled), filter-column, filter-or (-s, -o, across stages), filter-count,
  filter-k, filter-na (+ -msg), filter-ne, filter-int and filter-int-eq (largest i64, an
  integer beyond i64, 1e3 = 1000, -0 = 0; same results with int128), filter-hint,
  filter-errors, filter-unknown, filter-sam, filter-bam. sel-unsupported: '@x/gt/0' is now a
  filter, replaced by '@assert@x/gt/0'. Help references updated. Unit tests in num.rs (parse,
  comparisons) and filter.rs (parsing, comparisons). make test-int128 passes.


Item 2: = /= ~ /~

  Files: src/filter.rs (Op::Match, regex in FilterSpec, Operand::Regex), opt.rs (help),
  Cargo.toml (memchr as a direct dependency; it was already compiled as a dependency of regex,
  so nothing new is downloaded).

  = and /= map onto Op::Str(Cmp::Eq) and Op::Str(Cmp::Ne): they are the same byte equality as
  ~eq~ ~ne~, with the same column-name hint. An empty VALUE is allowed (@x= selects empty
  fields). ~ and /~ are Op::Match(negated). find_operator() was already in place: a /xx/ or
  ~xx~ token takes precedence, else the first '=' or '~' (with a preceding '/') ends NAME.

  A constant pattern is compiled in parse_filter() with io::compile_pattern (regex::bytes,
  Unicode mode off, as -/PAT), so a syntax error, a backreference or look-around is an option
  error with the regex crate's message. An empty pattern (also ^ with nothing after it) is
  refused. The compiled Regex is kept in FilterSpec, which therefore no longer derives
  PartialEq (Regex has no equality); compile() clones it into the Filter (a clone of a Regex
  is cheap, it shares the compiled program).

  With :NAME the other column's value is searched as a fixed string with memchr::memmem::find
  (step7.txt item 2 has the rationale). pick prints "-- column x entries will be used as
  regular expression --" and matches per row as a regex; the test filter-regex-column shows
  the difference (axbcd ~ '.' and abcd ~ 'b|c' are kept by pick, not by pluk).

  Checked against pick: filter-regex (all twelve invocations) and filter-regex-count give
  identical output; big-count (@n1/gt/0 @grp=B) agrees with pick's ref.

  Speed: 1,000,000 rows, pluk -c 0.03 s without filter, 0.05 s with @a~_1.*_x, 0.04 s with
  @a~:b, 0.03 s with @a=read_5_x.

  Tests: filter-regex (labelled: = /= with and without VALUE, ~ /~ in both stages, anchors,
  alternation, %5E for a literal-start '^' after ^, (?i), \w, %2F), filter-regex-column and
  -neg (metacharacters and empty values in the pattern column), filter-regex-count (-c with
  /= and ~ across stages), filter-regex-errors (empty patterns, regex syntax, backreference,
  look-ahead, extra arguments). filter-errors: @x=3 and @x~a removed (now valid). Help refs
  updated. Unit tests in filter.rs (parsing_eq_match; error cases extended).


Item 3: ~isin~ ~isnotin~ ~hasval~ ~hasnotval~

  Files: src/filter.rs (Op::IsIn, Op::HasVal, the extra argument, Operand::Dict), dict.rs
  (Dicts::get), main.rs (compile() gets &dicts), opt.rs (help).

  Parsing. VALUE and the extra argument are now split generally: VALUE ends at the first '/'
  or '~', and extra_rule(op) says whether the operator refuses the rest (Extra::No) or
  requires it with a given separator (Extra::Required(b'~') for ~hasval~ ~hasnotval~). Item 4
  adds Extra::Optional(b'/') for /ep/ /om/. The extra argument is %-decoded; a further '/' or
  '~' in it is refused, a leading ':' is reserved. For dictionary operators VALUE must be a
  plain name (no ':' or '^').

  Compilation. Dictionary names are resolved in Filters::compile, after the header has been
  read, because seqlen (SAM) and the --td column dictionaries only exist then. Rust note: the
  filter keeps a reference to the dictionary's HashMap instead of a copy or an index. A
  reference stored in a struct needs a lifetime parameter: Operand<'d>, Filter<'d> and
  Filters<'d> say "this borrows something that lives at least as long as 'd", here the Dicts
  in main(). The compiler then checks that dicts is neither dropped nor modified while the
  filters exist (add_sam_lengths, which modifies dicts, runs before compile). The C analogue
  is a const pointer into a table that must outlive its users, but checked at compile time.

  Evaluation. HashMap<Vec<u8>, Vec<u8>> can be queried with a &[u8] (Vec<u8> implements
  Borrow<[u8]>), so the field is looked up without allocating. ~hasval~ compares the stored
  value with the extra argument as bytes. Defaults and __EXIT__ are not consulted, as pick
  (pick keeps the default outside the hash and tests defined()).

  Checked against pick: big-isin equals pick's ref; filter-dict (nine labelled invocations),
  filter-dict-or, and ~isin~seqlen / ~isnotin~seqlen on sam.txt give identical output (pick's
  '-- 1 times a reference sequence length lookup failed' comes from its SAM processing, also
  without the filter). The unknown-dictionary message differs (pick: a Perl die).

  Speed: 1,000,000 rows, 100,000 keys from --kd: pluk -c 0.055 s without filter (including
  loading the keys), 0.095 s with @a~isin~K or ~isnotin~K, 0.067 s when no field is a key
  (short keys hash faster). About 40 ns per lookup with SipHash; noted in deferred.txt.

  Tests: big-isin (from pick, with pick's ref; big.keep.txt copied from pick/test),
  filter-dict (~isnotin~, ~isin~ in the @@ stage, ~hasval~ with a value, an empty value and a
  %-encoded ':', ~hasnotval~, a dictionary with a default and one with __EXIT__),
  filter-dict-or, filter-dict-sam (seqlen), filter-dict-bam, filter-dict-errors. Help refs
  updated. Unit tests in filter.rs (parsing_dict; error cases extended).
