
Notes for plan/step28.txt (the manual: sections 1-3 and the operator reference).


Planning

  Agreed: shared examples for sibling operators (about 120); a separate numbers file for
  awkward values; no comparison of the crates with Perl modules, instead a neutral note
  that pluk is relatively lean and why, with measured numbers (8 direct dependencies, 56
  further crates compiled, Cargo.lock listing 77 packages of which the rest are optional
  or for other platforms; about 12,000 lines, 107 unit tests; the noodles crates about
  34 of the compiled ones).


Item 1: sections 1-3

  Section 1: what pluk is; building (cargo build, make test, make test-int128 and what the
  int128 build changes); the eight crates with their use, and the leanness paragraph.
  Section 2: quick start, ten tasks in four tested blocks (columns, rows, a compute and a
  test, compressed input and SAM). Section 3: rows and the header (-k -K -h -R -u; options
  before the other arguments), writing names and values (%-encoding, -z -zz, \Q..\E),
  bytes, numbers (exact integers, overflow to float, round-trip floats, --num-perl,
  division by zero), NA, messages, reports and exit status (-q, -E<N>). New data file
  doc/numbers.txt (id x y: integers, a negative, the largest 64-bit integer, decimals,
  nan, an empty field, a word, 1e300).

  Facts checked by running pluk before writing: options after a column argument are taken
  as column names; -R names the unnamed column _; a '^' in a filter's regex needs no
  encoding; files written by name (--other, --assert-other, --demux) are gzip-compressed
  when the name ends in .gz (stdout is not); div by zero inf, idiv NA, sqrt(-1) nan. A
  first draft said that a dictionary default of NA gives NA; it gives the text NA (len 2),
  and the sentence was removed.

  The examples run the default build also in make test-int128: the documents call pluk,
  and doccheck.py puts the directory of p (target/release/pluk7) first on the PATH, where
  the default pluk lives as well. The manual describes the default build (the Numbers
  example shows the 64-bit overflow to float); this is as intended.

  Tests: the 17 examples of sections 2 and 3 pass doccheck.py (make test: 37 examples).


Item 2: reference for stack, string, regex (38 operators)

  Descriptions from the operator decisions (step13 for the string operators, step14 for
  the regex operators, step17 for cgsum cgmax cgcount): what the operator does, then NA,
  non-integer counts, edge cases, constant patterns. Sibling operators share one example
  (dup pop xch; cat len; lc uc rev rot13; head tail skip shed; ppl ppr zp; catall joinall
  join; urlec urldc; cgsum cgmax cgcount; del delg; ed edg; get npat; edbr edgbr): 19
  examples, on harvest.txt, numbers.txt and reads.sam.

  Method: the examples were written as commands and their output was produced by running
  them (an authoring script, not part of the repository), then read against the text.
  This caught one wrong claim in the draft: '$$' is not an escape in edbr's replacement;
  a '$' not followed by a digit is literal ('$$1' gives '$' and group 1). One example was
  changed to show the row that matters (uie on the empty field).


Item 3: reference for arithmetic, math, precision, bit, radix (57 operators)

  Rules from step12 (division by zero, floored idiv and mod, floats to integer operators
  NA, overflow to float, ipow NA on overflow, halves to even, whole-stack operators and the
  empty stack, rand and --seed), step15 (bit operators on absolute values, float NA, shift
  limits; radix with sign and magnitude, the strict reading rules) and step24 (qnl qnu,
  which are in the math category). 16 examples, on numbers.txt, harvest.txt and small
  printf inputs; the qnl example writes its step file in the example itself (the
  documentation examples run in a copy of doc/).

  A first trig example used pi/2, where the tangent is a meaningless 1.6e16 from floating
  point; replaced by 0 and 1.


Item 4: reference for dictionary, branch, state, time, bio (25 operators)

  Rules from step15 (map and dord, test and ifelse, registers, row numbers, time), step23
  (pload, groupi groupno) and step21 (the bio operators). 15 examples. Three needed care:
  now changes with every run, so its example tests that it is past 2001; todate depends on
  the time zone, so its example sets TZ=UTC; the group example sorts harvest.txt by fruit
  inline (a group is a run of consecutive rows).

  Reading the outputs led to two changes: the map example now includes a fruit that is not
  in the dictionary (the default 'none', and NA from dord), and the save text says that
  registers are shared by the computes of a row (the example fetches in one compute what
  another saved).


Item 5: reference for SAM, part 1 (31 operators)

  isforward; positions and lengths (ref_len ref_posx ref_posy qry_len qry_posx qry_posy);
  the trail and matched counts (_N, _V); the CIGAR parts; aln_nmatch aln_nedit
  aln_nmatchx; qry_seq qry_qual; the reference and read sequence parts; sam_get sam_put.
  The general rules (orientation, the definition of the trails and the matched part, NA
  for unmapped records) are given at the first operator of each group. Rules from
  SAMVIEW.design.txt and step17, step18, step25.

  New data file doc/align.sam (against transgene.fa): read1 of reads.sam with NM and AS
  tags; a secondary of read1 with SEQ '*' (filled from read1); read2 on the reverse
  strand with a hard clip and one mismatch; an unmapped read3. 10 examples; every count
  was checked by hand against the definitions.


Item 6: reference for SAM, part 2 (33 operators)

  The alignment strings (the symbols, the ruler, the quality line, dangling runs and
  context), aln_all aln_allq aln_all_pack (--sam-aln-prefix), aln_nedit_pia piu,
  aln_posinfo, patchiness patchiness2, and the region-bound tally (sam_rbt, --sam-rbt,
  the clipped region, the counts, the strings). Rules from step18, step19 (context, edit
  counts) and step20. 12 examples on align.sam and transgene.fa.

  Reading the outputs led to changes: the secondary of read1 (an alignment of mismatches)
  made the examples long and unclear, so they leave out secondary and unmapped records
  (@@2/none/260) or select read1's primary (@@2=0); the alignment pictures of aln_allq and
  rbt_alnall are shown in full (the authoring script elided after four lines). The second
  patchiness example first piped a bare alignment string into pluk: patchiness is a SAM
  operator (step18) and needs --sam, and --sam refuses input that does not look like SAM,
  so the example produced nothing; it now gives the string as a constant on align.sam.
  The authoring script now warns about a command without output (it had shown only
  stdout); a scan of the manual found no other empty example.
