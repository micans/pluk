step4 notes: decisions and rationale for implementation choices.


Decisions taken before implementation

  Differences from pick, decided explicitly:
    - --td^key/default=path: key before default. pick has /default^key; pick given ^key/default
      takes 'key/default' as the key column name.
    - Defaults in dictionary options are %-decoded (as -/PAT), so '=' can be written %3D.
    - No named table dictionaries, hence no tmap (see below).
    - Repeated NAME merges with a diagnostic; pick merges silently. __EXIT__ is sticky.
    - A table column name equal to an existing dictionary name merges with a diagnostic; pick
      merges silently.
    - Only --sam/f.fasta sets the SAM reference. In pick the first fasta dictionary loaded,
      including --fasta-dict-NAME, becomes the SAM reference.
    - seqlen is a reserved dictionary name. In pick --sam discards a user --fdict-seqlen.
    - In a fasta file a '>' line without identifier, and a repeated identifier, are errors. pick
      appends the former to the previous sequence and lets the latter overwrite.

  Table dictionaries without NAME

    Only the unnamed form of pick is implemented: every non-key column becomes an ordinary
    dictionary named after its header, used with ^COLNAME,map. This is consistent:
      - there is one flat namespace of dictionaries and one lookup operator, map. A dictionary
        name in a compute resolves to a single dictionary, so the compile-time replacement of
        ^NAME,map by ^<offset>,map covers all kinds. tmap would have needed a pair
        (table, column), resolved from two constants.
      - merging (repeated NAME) applies to table columns in the same way as to --fd and --cd.
      - the table name was only a prefix that kept column names apart. Without it, two tables with
        a column of the same name merge, with a diagnostic. If this becomes a problem, a later
        option could add a prefix to column dictionary names; this is not needed now.
    A consequence for storage: since a table column can merge with any other dictionary, each
    column is stored as an ordinary dictionary with its own copy of the keys (as pick does),
    rather than sharing one key index per table. Sharing would save memory for wide tables but
    complicates merging; it can be revisited if memory becomes an issue.
    The key column itself does not become a dictionary.

  Load order

    Option parsing records dictionary specifications; dictionaries are loaded afterwards, in the
    order given, so merge order is command-line order. Later, a syntactic parse of filters and
    computes will sit between option parsing and loading, so a syntax error fails before a large
    file is read. Name resolution (columns, dictionaries) follows loading and the header.

  Item 4a split from item 4

    The length check of --sam/f.fasta needs the seqlen dictionary filled from @SQ header lines,
    which pluk did not yet parse. Item 4 provides the reference; 4a adds seqlen and the check.


Item 1: --kd, --fd, --cd

  Files: src/dict.rs (new), opt.rs (parsing), io.rs (open_buffered), main.rs (loading, --test-dict).

  Parsing. parse_long() first checks the six prefixes kd- kdict- fd- fdict- cd- cdict-
  (dict_option), then parse_dict_spec() splits NAME[/DEFAULT]=SOURCE: NAME is the longest run of
  [A-Za-z0-9_] (pick: \w+), DEFAULT runs to the first '=' and is %-decoded, SOURCE must be
  non-empty. The result is a DictSpec stored in Config.dicts in command line order; the whole
  option is kept for messages. A default is stored as Option<NotFound>: None means no default
  was given, which matters when merging. NotFound::from_default() turns __EXIT__ (after
  decoding, so %5F_EXIT__ counts too) into NotFound::Exit.

  Storage. Dicts holds a Vec<Dict> and a HashMap from name to Vec index, as planned for
  compile-time resolution. A Dict is a HashMap<Vec<u8>, Vec<u8>> plus its NotFound. Values of
  --kd are stored as "1" like any other value; a separate key-only representation would save a
  small allocation per key but adds a second code path to lookup.

  Loading. main.rs calls Dicts::load() after option parsing and the no-columns check, before
  STDIN is read. get_or_create() returns the existing dictionary for a repeated NAME (message on
  STDERR, default replaced unless the current one is __EXIT__) or appends a new one. Files are
  opened with io::open_buffered(), the gzip detection moved out of LineReader::from_stdin() so
  that both use it. Files are read as pick does: the key is the first TAB-separated field;
  --fd takes the second field as value, or 1 if the line has one field; --kd always 1. A
  repeated key takes the last value. Lines are not checked for '\r' (pick's chomp neither).
  File paths are taken as bytes (OsStr::from_bytes), like the other arguments.

  --cd differences from pick: an empty pair (',,' or a trailing ',') is ignored (pick adds the
  key '' for an inner empty pair); a pair with two or more ':' is an error (pick silently drops
  the part after the second ':').

  Error messages: syntax errors are option errors, without 'pluk:' prefix, as the other option
  errors; read errors carry the 'pluk:' prefix. All exit 1.

  Values checked against pick with ^x,map lookups (--fdict from data.txt, a file with one-field
  lines and an empty key, --cdict with %-decoding and a default, --kdict).

  Speed: a 1,000,000-line --fd file loads in 0.41 s (pick: 4.3 s).

  Tests: --test-dict (temporary, runtestopt) prints each dictionary: name, not-found setting,
  number of keys, then sorted key TAB value lines. New tests dict-fd, dict-kd-gz (via process
  substitution), dict-big, dict-fd-fields, dict-cd, dict-exit, dict-merge (+ -msg),
  dict-merge-exit, dict-errors. o.help.ref and o.help-long.ref updated for the dictionary
  section of the help text. Unit tests in opt.rs (dict_options) and dict.rs.


Item 2: --td, --tdict, --table-dict

  Parsing (opt.rs). table_option() recognises table-dict, tdict and td (longest first) when the
  next byte is one of ^ / = -; anything else falls through to "Unrecognised long option", so
  --tdx=f is not taken as a table option. parse_table_spec() reads [^KEY][/DEFAULT]=FILE:
    - '-' after the option name (--td-NAME) is refused with a message pointing to the
      supported form.
    - KEY extends to the first '/' or '=' and is %-decoded, so a column name containing '/' or
      '=' is written with %2F or %3D. An empty KEY is an error.
    - A '^' in DEFAULT is refused. pick's order is /DEFAULT^KEY; without this check
      --td/d^k=f would silently become the default 'd^k' with the first column as key. A literal
      '^' in a default is written %5E.
    - [/DEFAULT]=SOURCE is now parsed by parse_default_source(), shared with item 1.
  DictSpec gained key_column; for a table, name is empty.

  Loading (dict.rs, Dicts::read_table). The first line gives the column names. The key column
  is the first column, or the one named by KEY. For every other column get_or_create() yields a
  dictionary named after the column (merging, with message, as in item 1); its index is kept in
  targets, so that each data line is distributed over the dictionaries by position. get_or_create()
  now takes the name separately from the spec, since table dictionaries take their name from the
  file. read_line() is shared with read_file().
  Checks, as in pick: an empty file, KEY not found, a line whose number of fields differs from
  the header, and a repeated key are errors (pick: "Table read error", "Repeated key"). A
  repeated key is detected with a HashSet of the keys of this table, not with the dictionaries
  themselves, since those may already contain the key from an earlier merge.
  Difference from pick: a repeated column name in the table header is an error; in pick the
  later column overwrites the earlier one in the same dictionary.
  A table with only a key column creates no dictionaries; a header without data lines creates
  empty ones.

  Values checked against pick with ^col,map lookups (--tdict=data.txt, --tdict/DF^dna).

  Speed: 1,000,000 rows with 3 value columns load in 2.1 s (pick 5.5 s): per row three
  dictionary inserts plus one insert in the repeated-key set, each copying the key. The faster
  hasher in deferred.txt applies here as well.

  Tests: tdict, tdict-key, tdict-big-gz (^id, __EXIT__, gzip), tdict-keyenc (%2F in KEY),
  tdict-merge (+ -msg; with --fd and --cd, __EXIT__ sticky), tdict-headeronly, tdict-keyonly,
  tdict-errors (option errors and table errors), tdict-errors-file (repeated column name, field
  count, repeated key). Unit test table_options in opt.rs. o.help.ref and o.help-long.ref
  updated for the --td lines.


Item 3: --fasta-dict-NAME

  Storage: owned values, not one buffer with ranges. The step file proposed reading the file
  into a large buffer with sequences as slices (ranges). Since item 1 every dictionary is a
  HashMap from owned key to owned value, and a repeated NAME merges, also across kinds (a fasta
  dictionary with --cd of the same name). Ranges into a buffer would need a second form of
  dictionary value, visible to merging and later to lookup. With owned values there is one
  form; peak memory is about the total sequence size, as each finished sequence is moved into
  the dictionary and trimmed to its length (a growing Vec may have up to twice the capacity it
  needs). The cost is one allocation per sequence, the same as one per value for --fd.

  Parsing (opt.rs). fasta-dict- is a seventh prefix in dict_option(); NAME/DEFAULT as item 1.
  A fasta dictionary without a default gets __EXIT__ (as pick), set in parse_dict_spec(), so
  that a fasta file merged into an existing dictionary also sets __EXIT__ (pick does the same,
  read_fadict sets dictnotfound).

  Reading (dict.rs, read_fasta). Line by line with read_line(). A '>' line starts a record; the
  identifier extends to the first white space (is_ascii_whitespace: space, \t, \n, \f, \r; Perl's
  \s also has \v). The following lines are appended to the sequence; empty lines contribute
  nothing. After the file, '*' maps to the empty sequence, as in pick (unmapped SAM reads).
  Lines are not checked for '\r', as pick (chomp).
  Differences from pick, all errors: a '>' line without identifier (pick: appended to the
  previous sequence), a repeated identifier within a file (pick: the last one wins), and
  non-empty lines before the first '>' (pick: ignored). Empty lines before the first '>' are
  allowed. Repeated identifiers are detected with a HashSet of this file's identifiers, for the
  same reason as with tables (the dictionary may already have keys from a merge).
  Unlike pick, no message about SAM reference lookup is printed; only --sam/FILE (item 4) sets
  the SAM reference.

  Checked against pick with ^f,map lookups: multi-line sequences, description after the
  identifier, empty sequence, '*', a default, and __EXIT__ failing.

  Speed and memory (peak RSS):
                                                      pluk               pick
    5 sequences, 200 MB, 60-char lines                0.15 s  193 MB     9.3 s  243 MB
    1,000,000 sequences of 100 bases (110 MB)         0.98 s  353 MB     6.8 s  275 MB
  For many short sequences the overhead per record dominates: two owned Vecs (id, sequence),
  the hash map entry, and the id copy in the repeated-identifier set. If this matters, the
  buffer-with-ranges design is the remedy, at the cost discussed above.

  Tests: fadict (multi-line, description, empty sequence, leading empty line), fadict-gz (with
  default), fadict-merge (+ -msg; __EXIT__ set by the fasta merge, kept after --cd/d2),
  fadict-errors-file, fadict-errors. Fasta inputs are written with printf in the Makefile; tests
  whose messages contain the file name use a temporary file fa.tmp rather than process
  substitution, as /dev/fd/NN may differ between systems. Unit test additions in
  opt.rs (dict_options). o.help.ref and o.help-long.ref updated.


Item 4: --sam/FILE, --sam-h/FILE

  The SAM reference is an ordinary fasta dictionary named SAMFA, as in pick, with default
  __EXIT__. Keeping pick's name means a compute can use ^SAMFA,map as in pick, and the SAM
  operators of a later step find the reference through the same name-to-index map as any other
  dictionary (dict::SAM_REFERENCE).

  Parsing (opt.rs). --sam/FILE and --sam-h/FILE act as --sam and --sam-h at their position
  (set_sam(), now shared, so the order rule for -O still holds: --sam/FILE -O3 gives -O3) and
  add a DictSpec of kind Fasta for SAMFA, loaded with the other dictionaries in command line
  order. An empty FILE is an option error.

  Reserved names. dict::is_reserved() lists SAMFA (item 4a adds seqlen). Dictionary options
  (--kd, --fd, --cd, --fasta-dict) refuse a reserved NAME; --td refuses a table with a non-key
  column of that name. pick allows --fdict-SAMFA, which silently mixes with the reference.

  Differences from pick:
    - --fasta-dict-NAME does not become the SAM reference (decided before implementation).
    - A repeated --sam/FILE merges into SAMFA with the merge message of item 1; pick reads both
      into SAMFA and prints its "multiple fasta dictionaries" warning only when a second fasta
      dictionary of another name is read.
    - pick prints "-- Sequences for SAM reference lookup loaded from FILE in dictionary SAMFA"
      at its default verbosity; pluk prints nothing (pluk has no verbosity levels yet).

  Test data: test/sam.fa (new), the reference for test/sam.txt: chr1 of 1000 and chr2 of 500
  bases, as in its @SQ lines, 60 bases per line. Random bases (Python, seed 42), with the
  aligned parts of the reads written in at their positions (r001, r002, r004, r006, r007, r008;
  r003 has an invalid FLAG and does not match), so that later SAM operator steps have a
  consistent reference.

  Tests: samref-A and samref-h-sel (output identical to sam-A and samh-sel: the file changes
  nothing else), samref-dict, samref-dict-gz (with another dictionary), samref-merge (+ -msg),
  samref-errors (empty FILE, missing file, reserved name in --fd, --fasta-dict and a --td
  column). In opt-errors, --sam/x.fa ("not yet supported") is replaced by --sam/ (empty
  FILE); o.opt-errors.ref changed accordingly. Unit test sam_reference in opt.rs. Help
  references updated.


Item 4a: SAM sequence lengths (seqlen) and the reference length check

  Where seqlen lives. All dictionaries are kept in Dicts, which main owns; the input reader
  should not need access to it. io.rs therefore only collects the @SQ lengths
  (LineReader.sam_seqlen) while read_first() reads up to the first data line, and main calls
  Dicts::add_sam_lengths() right after LineReader::from_stdin(). That is the point where pick
  runs its check too (at the first data line), and the header is complete then: SAM puts @SQ
  lines in the header, before the alignments.
  Difference from pick: an @SQ line after the first data line is not used. pick adds it to
  seqlen while streaming. pluk reports the first such line on STDERR and ignores them.

  Reading @SQ lines (io.rs). In SAM mode (--sam, --sam-h, with or without FILE) every line
  starting with "@SQ<TAB>" is examined before the pass/skip decision, so user patterns such as
  -/^@SQ do not hide it. parse_sq() takes the SN: and LN: fields in any order; pick's pattern
  /SN:(\S+)\s+LN:(\d+)/ requires SN directly before LN. A line without SN, with an empty SN, or
  without a numeric LN is reported (pluk: @SQ line N without SN: or valid LN: field, ignored);
  pick ignores it silently. A repeated SN takes the last length, as in pick.
  in_preamble marks the reading of the first line; read_first() is split into a wrapper that
  clears the flag and read_first_line(), so the flag is cleared on every exit path.

  seqlen (dict.rs, add_sam_lengths). Created in SAM mode, with not-found value 0, as in pick;
  values are decimal byte strings like any other dictionary value. With SAMFA present the check
  follows pick's sam_check_reflen: for each reference sequence (sorted, '*' excluded) a length
  missing from the header is taken from the fasta; a disagreement is reported and the header
  length kept; then a summary line, always printed (pick prints it at default verbosity):
      pluk: sequence chr1 has length 1000 in the SAM header and 4 in the reference; using 1000
      pluk: SAM reference lengths: header/fasta/shared/conflict 1/2/1/1
  pick's line is "-- [N] WARNING header/fasta length disagreement 1000/4 -- picking header/1000",
  without the sequence name. pick also adds '*' to seqlen with the fasta length 0; pluk leaves it
  out, as a lookup failure yields 0 anyway. The counts agree with pick on the tested cases.
  The per-line length lookup and pick's "N times a reference sequence length lookup failed"
  message belong to the SAM operators of a later step.
  seqlen is reserved (dict::is_reserved), refused for options and table columns as SAMFA.

  --test-dict now prints after the input header has been read (it previously exited before
  reading STDIN), so that seqlen is included. Tests with --test-dict and SAM mode therefore show
  seqlen as well: samref-dict, samref-dict-gz, samref-merge and samref-merge-msg (summary line)
  changed accordingly.

  Tests: seqlen, seqlen-ref (+ -msg), seqlen-conflict (+ -msg; chr2 missing from the header,
  chr1 shorter, chr3 only in the fasta), seqlen-malformed (+ -msg; repeated SN), seqlen-late
  (in runpluk, @SQ after the alignments, with -c), seqlen-nosam (no seqlen without SAM mode),
  seqlen-errors (reserved name in --fd, --cd and a --td column). Unit test sq_fields in io.rs.
