step12 notes: decisions and rationale for implementation choices.

  Decisions: step12.txt (decisions 1-12) and NUMERIC.design.txt section 9 (NA and NaN).


Item 1: NA and NaN; /ISNUM on nan

  Files: NUMERIC.design.txt (section 9), filter.rs (Filter::predicate), opt.rs (help).

  /ISNUM now holds for numbers other than NaN (and /NOTNUM for NaN): a NaN from parsing
  (nan, NaN) is not a usable number. inf and -inf remain numbers. The parser is unchanged:
  nan still reads as a float for arithmetic and comparisons. Rationale in
  NUMERIC.design.txt section 9 (guards against missing values; pandas, numpy and R write
  NaN for missing).

  Tests: filter-pred and filter-pred-multi (the nan row moves from /ISNUM to /NOTNUM),
  help refs; the unit test in filter.rs adds NaN and -inf.


Item 2: binary and unary arithmetic

  Files: num.rs (sub mul div idiv imod pow ipow replaces neg abs sign sq incr decr), ops.rs
  (table entries; numeric1, numeric2 and choose as shared implementations), opt.rs (help).

  The typed functions live in num.rs next to add: each matches on (I, I) and otherwise
  works in f64 (mixed operands promote, NUMERIC.design.txt section 3). Generic operators
  use checked_* and fall back to a float on overflow (sub, mul, neg, abs, sq, incr, decr).
  The explicit integer operators return Option<Num>, None meaning NA: idiv and imod for a
  float operand, a zero divisor and Int::MIN / -1 (Int::MIN mod -1 is 0); ipow for a float
  operand and overflow (u32 exponent; a larger one only for bases 0, 1, -1); a negative
  exponent behaves as pow. idiv and imod are floored: the quotient is rounded towards minus
  infinity and the remainder has the sign of the divisor (Perl's %; pick's idiv is
  floor(x/y)), so x = y * idiv(x, y) + mod(x, y). div and pow always give a float; division
  by zero follows IEEE. sign gives -1, 0, 1 as integers; NaN stays NaN (pick: 0).

  In ops.rs most operators are one line: numeric2 pops y and x, gets their numbers
  (Machine::num, cached per field), and pushes the function's result or NA; numeric1 the
  same for one operand. Rust note: the helpers take the function as 'impl Fn(Num, Num) ->
  Option<Num>', so both plain functions (num::idiv) and closures (|a, b| Some(num::sub(a,
  b))) can be passed; each op_ function stays a plain fn, as the table needs.

  max and min choose an operand rather than computing a value: the winner is pushed as it
  was (a field stays a field), so 1.000000 stays 1.000000 and -65.4560 keeps its zero, as
  in pick (found by the comparison: a first version pushed the number and wrote 1 and
  -65.456). The choice follows pick: y replaces x if y > x (max) or y < x (min), so with a
  NaN the result is x.

  Checked against pick (--num-perl): math-arith (four invocations on data.txt: all
  operators on integer, negative and float columns) and math-arith-big (big.txt; without
  idiv and mod by zero, where pick dies with 'Illegal division by zero') are identical.
  math-arith-edge (pluk only): division by zero, 0/0, floats to integer operators, a
  non-number, negative divisors, nan, ipow overflow; values chosen so that the i64 and
  int128 builds agree (the integer boundaries are in the unit tests, which use Int::MIN and
  Int::MAX).

  Tests: math-arith, math-arith-big, math-arith-edge. Help refs. Unit tests in num.rs
  (arithmetic).


Item 3: rounding and functions

  Files: num.rs (round_with, to_int; to_f64 now public), ops.rs (Category::Math, table
  entries, float1), opt.rs (help).

  int floor ceil round: num::round_with(a, f) applies f64::trunc, floor, ceil or
  round_ties_even to a float and converts the result to an integer if it is finite and in
  the integer range (to_int); otherwise the whole float stays (1e300, inf, nan; decision 5).
  An integer operand is returned unchanged. round halves to even on the exact binary value,
  as pick's sprintf('%.0f') (2.5 -> 2, -2.5 -> -2); pick writes -0 for round(-0.4) and
  round(-0.5), pluk the integer 0.

  The functions (sqrt exp exp2 exp10 log log2 log10 sin cos tan) go through float1: the
  operand as f64, the result a float, domain errors as IEEE (log(0) -inf, log(-1) and
  sqrt(-1) nan; pick dies: 'Can't take log of 0'). log2, log10 and tan use Rust's direct
  functions (f64::log2, log10, tan); pick computes log(x)/log(2), log(x)/log(10) and
  sin(x)/cos(x), which differ in the last bit for some values (log10(8): pick
  0.9030899869919434, pluk 0.9030899869919435, the correctly rounded value; log10(1000) is
  exactly 3 in pluk, 2.9999999999999996 in Perl, shown as 3 by %.15g). With --num-perl such
  differences show when the 15th digit flips. exp10 is 10f64.powf(x), as Perl's 10**x.

  Checked against pick (--num-perl): math-func (rounding on floats and negative integers,
  sqrt log exp exp2 exp10, sin cos tan on data.txt) and math-func-big (rounding, sin, cos
  on big.txt floats; sqrt and log on n4) are identical. Not compared: log2, log10 and tan
  on big.txt (last digit, above), exp of large values (whole floats written as integers by
  --num-perl, decision 11), log of 0 (pick dies). math-func-edge (pluk only) shows these.

  Tests: math-func, math-func-big, math-func-edge. Help refs. Unit test in num.rs
  (rounding).


Item 4: whole-stack operators

  Files: ops.rs (whole, choose_all, op_mulall ... op_gmeanall; op_addall now uses whole),
  num.rs (Num::is_nan), opt.rs (help).

  whole() takes the stack (std::mem::take, so its capacity is reused), gets the numbers,
  empties it and pushes the function's result: NA if any value is not a number or if the
  function has no result. addall and mulall fold with num::add and num::mul (integers stay
  integers, overflow to a float), 0 and 1 for an empty stack as pick. meanall is the sum
  divided by the count (num::div, a float). hmeanall and gmeanall use pick's formulas,
  including the absolute values: n / sum(1/|x|) and (product |x|)^(1/n). A zero makes the
  harmonic mean 0 (IEEE n / inf; pick dies on 1/0). The geometric mean multiplies directly,
  as pick, so many large values can overflow to inf; a mean of logarithms would avoid that
  but change the last digits against pick (not done).

  maxall and minall (choose_all) push the winning operand itself, as max and min (1.50
  stays 1.50; of equal values the first wins). pick starts from -DBL_MAX (DBL_MAX) and
  replaces on > (<): NaN never wins, and -inf never wins either, so maxall(-inf) is
  -DBL_MAX in pick. pluk starts from the first value, replaces with num::replaces, and lets
  any number replace a NaN: NaN never wins unless all values are NaN (then NaN), and
  maxall(-inf) is -inf.

  Empty stacks: meanall, hmeanall, gmeanall, maxall and minall give NA (decision 9; pick:
  0, 0, 1, -DBL_MAX, DBL_MAX).

  Checked against pick (--num-perl): math-whole (three invocations, on data.txt integers,
  negatives and floats and on big.txt) is identical. math-whole-edge (pluk only): NaN, all
  NaN, -inf, a non-number, a zero, equal values with different spellings, empty stacks.

  Tests: math-whole, math-whole-edge. Help refs.


Item 5: precision operators; gmeanall from logarithms

  Files: num.rs (write_fixed), exec.rs (Machine::perl), ops.rs (Category::Precision, STR,
  precision, op_dd ... op_pml; op_gmeanall), opt.rs (help).

  dd and sn write x with N digits after the decimal point (pick's sprintf %.*f and %.*e);
  frac, pct and pml write x/y, x*100/y and x*1000/y the same way (computed in this order,
  as pick). The result is text (Kind::Str), e.g. 3.50; an operator that needs a number
  parses it again. num::write_fixed uses Rust's {:.*} and {:.*e}, which round the exact
  binary value half to even, as glibc's printf (0.125 with 2 digits is 0.12); the exponent
  is rewritten as C writes it (1.23e+05). inf and nan are written as other numbers: inf and
  nan, or Inf and NaN with --num-perl (as Perl's sprintf), which is why the operator needs
  Machine::perl(). N is the top operand: a non-negative integer up to 1000 (a cap so that a
  wild value cannot produce megabytes of digits), otherwise NA, as for any operand that is
  not a number. Division by zero follows IEEE (pick dies).

  gmeanall (decided after item 4): exp(mean(ln|x|)) instead of pick's (product |x|)^(1/n).
  The product overflows to inf for long stacks of large values (five times 1e200 is inf in
  pick; 1.000000000000022e+200 in pluk); the logarithms do not, at the cost of last-digit
  differences against pick. A zero gives ln 0 = -inf and so a mean of 0. gmeanall was
  removed from the pick comparison math-whole and has its own test, math-gmean.

  Checked against pick (--num-perl): math-precision (data.txt floats, negatives, integers;
  big.txt; 20 and 15 digits) is identical; math-whole (without gmeanall) still is.
  math-precision-edge (pluk only): division by zero, 0/0, N negative, a float, not a
  number, beyond 1000, x not a number, an exact binary tie, Inf and NaN with --num-perl.

  Tests: math-precision, math-precision-edge, math-gmean; math-whole changed (gmeanall
  removed). Help refs. Unit test in num.rs (fixed).


Item 6: rand and --seed

  Files: exec.rs (SplitMix64, clock_seed, Machine::random; Machine::new takes the seed),
  ops.rs (rand), opt.rs (--seed=N, help), main.rs.

  The generator is splitmix64 (Steele, Lea and Flood, 2014): a 64-bit state advanced by a
  constant and mixed by shifts and multiplications; a float in [0, 1) takes the top 53
  bits. About ten lines, no dependency (Rust's standard library has no generator). It is
  not cryptographic and needs not be. The state lives in the Machine; each rand call
  advances it, in row order and compute order, so --seed=N gives the same output for the
  same command line and input. Without --seed the seed is the clock (nanoseconds) mixed
  with the process id. pick has no seed (Perl's rand, seeded by Perl).

  rand follows Perl's rand(x): a float in [0, x); x = 0 counts as 1 (perldoc -f rand); a
  negative x gives (x, 0]; not a number gives NA.

  Tests: math-rand (fixed seed: values for 1, 10, 0, -5 and a non-number; range assertions
  on 100 rows for 10 and -3; a bad seed). Unit test in exec.rs (splitmix: reference values
  for seed 0, floats in [0, 1) with mean near 0.5). Help refs.
