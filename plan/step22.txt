
- Filter synonyms; the test setup

  A small step (plan/remaining.txt C a and b).


  Outcome of the discussion

  Decisions:
   0. ~notin~ is a synonym of ~isnotin~, ~notval~ of ~hasnotval~ (plan/sketch: 'aliases to
      be consistent'). They are accepted wherever the long names are: @ and @@ filters,
      multi-column handles, and test (~notin~ with a constant dictionary as ~isnotin~;
      ~notval~ refused in test, as ~hasnotval~). -l lists them on their own lines, as
      'synonym of ..', in the filter category. pick has neither: a pluk addition, listed
      in guidelines.txt.
   1. A filter written @x~notin~D or @x~notval~D~v was until now an error ('unrecognised
      operator': any ~letters~ is read as an operator name), so no existing filter changes
      meaning. (Corrected in item 1; the draft assumed the regex filter ~.)
   2. The test setup (the user's questions: how idiosyncratic it is; whether all tests can
      run with the failures tallied; answered in step22-notes.txt). The golden-file setup
      stays (no test framework crate). Four changes to test/Makefile:
      - .IGNORE: runpluk runtestopt, so that a failing invocation does not stop the others;
      - rundiff compares every reference with its output (cmp, whatever the file times),
        reports 'missing' and 'differs' (with the first lines of the diff) for each, and
        ends with '--- N of M tests failed: names ---' (exit 1) or '--- M tests compared ---';
      - runpluk removes all o.*.test first, so that an output no longer produced shows up
        as missing instead of passing with a stale file;
      - make accept T='name ..' copies o.<name>.test to o.<name>.ref (o. and .test/.ref
        may be given).
