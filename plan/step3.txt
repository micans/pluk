  2   Parsing structure (decided). Follow pick:
        - Command line words are processed left to right while they start with '-'; a bare '--' ends the
          options. The remaining words are column arguments.
        - A '--' option is one per word and is not bundled.
        - '-' options can all be bundled in one word. pluk scans a bundle left to right, character by
          character, so that an error can point at the offending character (pick removes known parts
          with substitutions; the accepted bundles are the same).
          Unknown characters are an error with pick's message:
            Option string not fully parsed: <rest> remains
        - Order rule: options take effect left to right, the last one wins, as in pick. Thus
          'pluk --sam -O3' uses 3 and 'pluk -O3 --sam' uses 12. This replaces the explicit -O priority
          of step2 item 4.
        - O<num> requires attached digits, as in pick: -O8 and -kO8 are valid, -O 8 is an error.
        - A<num> takes optional attached digits, possibly negative (-A, -A4, -A-1), as in pick.
          -A <num> is not supported (<num> could be a column name). <num> is parsed and stored but not
          yet acted upon (insert position for computed columns).
        - /PAT and //PAT must be part of a '-' word: -/PAT, -//PAT, or at the end of a bundle, e.g.
          -A4kO8/^#. A word without a leading dash is a column argument.
          Within a bundle, /PAT and //PAT extend to the end of the word; both can be given as
          -/PAT1//PAT2. A literal '/' inside a pattern is an error and must be written as %2F, so
          that -//PAT1/PAT2 is refused rather than read as the pass pattern 'PAT1/PAT2'.
          Patterns are %-decoded (%XX), as in pick.
