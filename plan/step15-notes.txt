step15 notes: decisions and rationale for implementation choices.

  Decisions: step15.txt (decisions 0-7). map and dord were added after the first plan:
  the survey of missing operators (from pick's operator table) stopped too early and
  missed map, dord and tmap.


Item 1: map and dord; dictionaries in computes

  Files: dict.rs (Dict::insert, Dict.order, Dicts::index_of/at, load with the ordered
  names), compute.rs (Attached, Instr::OpWith, Prepare::ConstDict, const_dict,
  dord_dictionaries; compile takes the dictionaries), exec.rs (Machine<'d> with the
  dictionaries, fail/fatal, run returns Result), ops.rs (OpFn takes &Attached; map, dord;
  Category::Dictionary), main.rs (Failure: Assertion or Fatal), opt.rs (help).

  Attached. The prepare step used to attach a compiled regex to an operator instruction
  (Instr::OpRegex). Now Instr::OpWith(op, Attached) carries Attached::Regex or
  Attached::Dict (the dictionary's position in Dicts), and every operator function takes
  &Attached (Attached::None for plain operators); a mechanical change of the OpFn
  signature. Prepare::ConstDict(pos) checks that the operand is a constant naming a
  dictionary ('Dictionary [Q] not found' otherwise, as the ~isin~ filters) and resolves it
  once. Rust note: the machine now refers to the dictionaries (Machine<'d> holds
  &'d Dicts), as the filters did since step7; Stages<'d> already had the lifetime.

  map applies the dictionary's not-found rule of step4: the key itself (the operand is
  passed on as it is), the default, or __EXIT__. __EXIT__ ends the run: the operator calls
  Machine::fail, run() stops after the compute and returns the message, and Stages::judge
  reports it as Failure::Fatal, which route() turns into an error with the line number
  even with --assert-other (Failure::Assertion is diverted there). The rows before it have
  been written (as pick, which dies).

  dord. Dict::insert records each key's first position (1-based, across everything merged
  into the dictionary) when the dictionary has an order table. Which dictionaries need one
  is decided before they are read, from the computes: a constant directly before dord
  (compute::dord_dictionaries; pick looks for ^D,dord in the arguments for the same
  reason). All readers (--kd --fd --cd --fasta-dict --td) now insert through
  Dict::insert. seqlen is built from the SAM header as a whole and has no order (dord
  gives NA). Absent keys give NA (pick: ~0, 18446744073709551615).

  Also: the format strings in compute.rs's describe functions contained raw newlines
  (valid Rust, written that way in step10); they are now \n escapes. The help text lists
  the operators by family.

  Checked against pick: dict-map (pick's test 123dict2, --cdict with and without a
  default, a name not in the dictionary, --kdict, --fdict) is identical. dord agrees with
  pick on every present key (3, 12 and 58 rows in the three comparisons) once pick's ~0
  for absent keys is read as NA.

  Tests: dict-map, dict-dord (order of single and merged sources, NA keys), dict-ops-edge
  (__EXIT__, a dictionary from a column, an unknown dictionary, seqlen with map and dord).
  Help refs.


Item 2: ifelse and test

  Files: filter.rs (Rhs, evaluate, numeric, operator, default_band, Outcome public;
  Filter::test now builds an Rhs and calls evaluate), compute.rs (Attached::Test,
  TestRhs, prepare_test), ops.rs (Prepare::Test, Category::Branch, op_ifelse, op_test),
  opt.rs (help).

  test reuses the filter code. The per-column evaluation that was a method of Filter is now
  a free function, evaluate(op, field, rhs, extra, band), whose right-hand side is a
  borrowed view (Rhs: a number, bytes, a compiled regex, a dictionary); a filter's column
  operand becomes bytes, which for ~ and /~ means the fixed-string match (the ~:NAME rule
  of step7). numeric(op, lhs, rhs, band) holds the numeric operators. Filters behave as
  before (the whole suite passes unchanged).

  Compile time (prepare_test): T, the top operand, must be a constant naming a filter
  operator (filter::operator, the token table of step7); ~hasval~ and ~hasnotval~ need a
  third value that pick's test never passes (so they cannot succeed in pick) and the
  predicates take no y, so both are refused. For ~ and /~ the pattern y must be a constant
  (const_regex at position 1); for ~isin~ and ~isnotin~ the dictionary name y
  (const_dict at position 1). The result is attached as Attached::Test(op, TestRhs).

  Run time (op_test): numeric operators get the machine's numbers (Machine::num, cached
  per field) rather than the text, so that a computed number is compared exactly also
  with --num-perl (whose text, %.15g, could round). Pass is 1, Fail 0; where a filter
  would reject the row for a non-number or non-integer (Outcome::NotNumber,
  NotInteger), test gives NA, and so does an NA operand. /ep/ and /om/ use their default
  bands.

  ifelse B x y passes x or y on as they are. B is true if it is a number other than 0
  (compared with the dispatcher, so 0.0 and -0 are false and nan is true, as Perl's !=),
  or else if it is not empty; an NA condition gives NA.

  Checked against pick: branch-test (test with numeric, string, =, regex, negated regex,
  bit, /ep/ and /om/ operators, dictionary tests, ifelse on numbers, words, 0.0, empty and
  floats; big.txt, including two compounds from pick's ops-branch test) is identical.

  Tests: branch-test, branch-edge (NA from non-numbers and non-integers, NA condition, six
  compile-time errors). Help refs.


Item 3: save fetch rowno r0wno lineno

  Files: compute.rs (Attached::Register, Registers: slots and the compile-time check),
  exec.rs (Machine: registers by slot and by name, rowno, lineno; set_registers,
  store_register, find_register; run takes the row and line number), ops.rs
  (Shape::Drop, Prepare::Register, Category::State, the five operators), main.rs (Stages
  counts data rows; judge takes the line number), opt.rs (help).

  (This item was interrupted once by an API usage limit; nothing of the first attempt
  had been written to disk, and it was redone from the plan.)

  Registers. While compiling, each constant register name of save and fetch gets a slot
  (compute::Registers), attached to the instruction as Attached::Register(slot, name).
  A fetch of a constant name needs an earlier save of that name in compute order;
  otherwise it is a compile-time error, unless an earlier save took its name from a
  column (then the name may exist at run time). The machine collects the slots from the
  compiled computes (Machine::set_registers): a Vec<Option<Value>> by slot, and a
  name-to-slot map for names that come from columns, which use the slot if the name has
  one and an overflow map otherwise. Both are cleared at the start of every row, as
  pick's line cache. save stores the value and leaves it on the stack: Shape::Drop pops
  the name's slot and keeps the value's. A missing register is NA.

  Positions. Stages counts the data rows it judges (before the filters, so rows later
  rejected count, as pick's $::Nrows); the header line is not a data row, with -k the
  first line is (row 1), lines skipped by -/PAT and pass-through lines are not data rows.
  lineno is the reader's physical line number (LineReader.n_lines, which counts skipped
  lines too, as Perl's $.). Both are passed to Machine::run.

  Checked against pick: ops-branch (pick test 125 of pick/test/Makefile, combining dord,
  map with a default, uie, test, ifelse, save and fetch across computes) is identical
  (pick has no ref file for it; ours was checked against a pick run). state-ops (save
  and fetch within and across computes, rowno r0wno lineno with an @@ filter, with -k,
  with lines skipped by -/PAT) is identical.

  Tests: ops-branch, state-ops, state-ops-edge (names from a column, registers cleared per
  row, two compile-time errors). Help refs.
