Item 1: the 'pluk:' prefix, the notes reworded

  The errors of option and argument parsing are printed in two places, opt.rs (every
  error of Config::parse, compute and filter parse errors included) and main.rs (-/PAT
  and -//PAT); both now write 'pluk: '. No message reaches them with the prefix already
  (no 'pluk: pluk:' in any test output). The notes:
    -- You used X (a column handle) as a constant in T test, did you want :X? --
        -> pluk: T: [X] is a column name used as a constant; for the column write :X
    -- a regex column name starts with '+', e.g. +X --   (second line of an error)
        -> pluk: hint: a regex column name starts with '+', e.g. +X
    -- range expansion produced some indexes out of range (now dropped)
        -> pluk: range [R] has indexes beyond the last column (dropped)
    Line N does not look like SAM format [..]  -> pluk: line N does not look like SAM [..]
    -- Identical output column names exist (will make unique)
        -> pluk: column [C] is given more than once; it is output once  (one line per
           repeated column, decision 4)
  --help: '@@NAME... as @, applied before computes (input columns only)'.

  61 golden files changed. Each was compared line by line with its .test by a script that
  accepts only these rewrites (the prefix added, or one of the six forms above); all 213
  changed lines matched (178 prefix, 16 SAM, 10 repeated column, 4 range, 2 constant, 2
  help, 1 hint) and nothing else differed, after which they were accepted. The existing
  tests cover every changed message, so no new test was needed for this item. The
  manual's section 13 is updated in the same item (three of its examples showed the old
  forms with 2>&1); make test-int128 passes as well.
